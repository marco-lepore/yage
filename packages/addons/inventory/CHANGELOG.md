## 0.1.0

### Minor Changes

- [#162](https://github.com/marco-lepore/yage/pull/162) [`bbd144d`](https://github.com/marco-lepore/yage/commit/bbd144df663a577e75598c7c9959da53f2955fd3) Thanks [@marco-lepore](https://github.com/marco-lepore)! - Add `@yagejs-addons/inventory`, the second YAGE addon: a slot-based inventory system with a headless model and one windowed slot view whose cell look is a swappable preset (icon grid or text rows).
  - **Headless core** (root entry `.`): `defineItems` catalog (ids derived from map keys, typed end-to-end through `Inventory<TId>`), the `Inventory` model owning the annoying-but-non-trivial logic — stack merge on add with partial acceptance (`{ added, rejected, reason, slots }`), two stacking behaviors (`"multi"` per-stack caps with overflow into new slots, `"single"` one capped total stack that rejects the excess), `move` (move/merge/swap with leftover) and `split` (both returning an `Outcome`
    `{ ok, reason? }` — `move` also carrying `effect: "moved" | "merged" | "swapped"` —
    so a refused gesture reports why instead of collapsing to a bare boolean),
    consolidate-and-`sort` (comparators over `SortEntry`; `byCatalogOrder`/`byName`/`byCategory`/`byQuantity` shipped), cross-inventory `transfer`/`transferSlot` (only what the target accepts leaves the source; anonymous `transfer` moves fungible stacks first then data stacks, payload intact), per-stack `data` payloads that never auto-merge (anonymous `remove` drains fungible units first then data stacks, returning what left in `RemoveResult.stacks` so instance payloads are never silently destroyed), `snapshot()`/`restore()` JSON round-trips (unknown ids and bad quantities dropped and returned; a bag that shrank between saves re-flows entries past the new capacity into free slots, dropping only what no longer fits), and typed model events (`changed`/`itemAdded`/`itemRemoved`/`rejected`/`action`). The root entry never transitively imports `pixi.js` or `@yagejs/renderer`.
  - **Rules in, consequences out**: what an inventory accepts is injected policy — an `accepts` predicate for section filters (a key-items pouch), an `InventoryConstraint[]` seam for capacity models beyond slot count (weight, currency caps) answering "how many more units may enter"; the most limiting constraint's `id` rides rejections as `constraintId`, and a `NaN`-returning constraint is treated as 0 (loud reject) rather than poisoning the result. What an action _does_ is the game's: `ItemActionDef` declares `id`/`label` + per-stack `available` gates (`ItemDef.actions` narrows per item), invocation returns an `Outcome` (`{ ok: false, reason: "empty" | "no-action" }` when the slot is empty or the action isn't offered) and emits the `action` event for the game to apply, `consumes: true` removes one unit after the event (the event's `consumes` flag says so, preventing handler double-removal), `closes: true` hints the UI shut. `count`/`has`/`remove` also take a data predicate `(data, stack) => boolean`, and `find`/`findAll` return a `LocatedStack` handle that `remove(ref)`/`transfer(target, ref)` accept — so a specific instance (the key that opens the boss lair) is first-class, not just reachable by a raw slot index. A stack's `data` type is per item: declare it with `instance: instanceData<T>()` on the def and `defineItems` captures a data map that `new Inventory({ catalog })` infers alongside the id union, so the `add` payload and the predicate's `data` narrow per item (a wrong field, or a payload on an item that declares none, is a compile error). An id-only type (`Inventory<TId>`) or an untyped catalog keeps the permissive `Record<string, unknown>`.
  - **`InventorySource` and `filteredView`**: `InventorySource` is the read/act/subscribe surface `InventorySession` and `InventoryController` depend on (`slots`/`capacity`/`used`/`catalog`/`on`/`getActions`/`invokeAction`/`sort`), narrower than `Inventory` — which implements it directly, the identity projection ("all items"). `filteredView(inventory, (stack, def) => boolean)` projects a SUBSET of one model's stacks into its own compacted, hole-free `InventorySource` — a hotbar showing only usable items while staying a live mirror of the same backpack, so an add or a `use` on either surface is the same mutation. `capacity` reads `undefined` on a filtered view (it has no size of its own); `getActions`/`invokeAction` take presented indices, remapped to the real slot via the view's `.modelSlot(i)` escape hatch; `sort` forwards to the whole model. The view subscribes to the model's `"changed"` only while something is watching it, so a set of pre-built, currently-inactive tab views costs nothing.
  - **`InventorySession`** (headless UI orchestrator): open/close, cursor + action-menu state machine, an input-agnostic driving API (`move`/`select`/`confirm`/`cancel`/`sort`/`toggle` via the type-erased `InventorySessionDriver`), live model re-presentation (the menu re-resolves when the stack under it changes), `setSource`/`getSource` to swap the presented source (a plain `Inventory` or a `filteredView`) for tabbed panels sharing one view, and channel contracts (`SlotsChannel` is the only required one — navigation geometry lives in the view, so the view answers "down" itself regardless of column count).
  - **`InventoryController`** (a `@yagejs/core` Component): mounts presenters, mirrors source + session events onto entity→scene engine events (`InventoryItemAdded`/`ItemRemoved`/`Rejected`/`Changed`/`Action`/`Opened`/`Closed`/`SelectionChanged` — model events fire with the panel closed too), attaches the input binding (omitted `input` defaults to the FULL set, keyboard/gamepad + pointer hit-testing wired to the controller's own presenters), and exposes the host-driven seam plus `setInputEnabled` focus gating for multi-panel setups (losing focus closes an open action menu). The item-id generic is inferred from `inventory` alone — no explicit type argument at the call site; `inventory` accepts a plain `Inventory` or a `filteredView` of one.
  - **Input bindings** (root, over `@yagejs/input`): `KeyboardInputBinding` (action-map polling incl. the one closed-panel control, `toggle`), `PointerInputBinding` (hover + click cells and menu rows through the presenters' `slotAtPoint`/`actionAtPoint` hit-test seams; click off an open menu dismisses it), `CompositeInputBinding`, and `inventoryControls(bundle)`.
  - **Presenters** (`./presenters` subpath): one `SlotsView` — a windowed `columns × visibleRows` layout with integer-row scrolling and ▲/▼ hints — parameterized by a swappable `CellPresenter`. Two built-in presets: `iconCell` (icon via `ItemDef.icon` or a colored-tile-initial fallback + quantity badge + cursor outline) and `rowCell` (`Name ×qty` rows + highlight bar). A "list" is `columns: 1` with `rowCell`; a text menu is `columns: 2`; there is no grid-vs-list branching. The action menu and the scroll hints follow the same render-delegate split: `ActionMenuView` and `SlotsView` own measurement, placement, and pointer hit-testing, while swappable `menuSkin` and `hints` presets own the drawing — so a custom look can never desync its hit-targets from what it draws. Plus `DetailView`, `InventoryChrome` (frame + title + `used/capacity` counter), all sharing one `PanelLayout` geometry owner; pure `cellGeometry` and `layoutActionMenu` modules keep placement, cursor, scrolling, hit-tests, and menu geometry in tested, renderer-free sources. Zero bundled assets.
  - **Zero-config factory + theme**: `createInventoryPanel()` assembles a wired bundle from one flat `InventoryTheme` (`defaultInventoryTheme()` matches the dialogue addon's palette). Cell geometry is per-instance factory options (`columns`, `visibleRows`, `cellWidth`, `cellHeight`, `gap` as a number or `{ x, y }`), each defaulting from the chosen cell preset; a per-axis constraint solver fills whatever you leave unset, and an explicit `bounds` derives the missing count or extent to fit (overdetermining an axis keeps the declared values, centers, and warns). The theme is a flat data object covering every pure value the built-in renderers consume — colors, sizes, alphas, radii, layer names — following a data-vs-code rule: data goes in the theme, new drawing code goes in a swappable preset (`cell` / `menuSkin` / `hints`), and behavior (placement, windowing, navigation) is changed by replacing a view. `frameAlpha` translucency applies to both the panel chrome and the action-menu popup, and every visual constant that reads as "look" is an optional field that derives when omitted: `borderWidth` → 1.5, `cellRadius` → `cornerRadius / 2`, `highlightRadius` → `max(cellRadius - 1, 0)`, `rowHighlightAlpha` → 0.22, `hintAlpha` → 0.6, `menu.highlightAlpha` → 0.45, `descriptionSize` → `textSize - 2`, `menu.padding`/`menu.rowGap` → 10/6, `headerGap`/`detailGap` → 10/10, `tileLetterColor` → `0x1a1a2e`. Opt-in `textured: { panel?, menu? }` swaps a surface's drawn frame for a stretched nine-slice (`{ texture, insets }`, serializable via `TextureInput`) — the panel keeps its dividers, the menu its bar + labels; omit for the Graphics default (still zero bundled assets). Standalone vs embedded is configuration, not API: `chrome: false` + `bounds` place the panel inside a host menu, `input: null` + `closeOnCancel: false` hand driving to the host's focus handling.
  - **Layers**: screen-space `INVENTORY_LAYERS` (orders 1050–1070), below the dialogue addon's so a conversation plays over an open inventory.

  Independently versioned (not part of the `@yagejs/*` fixed group). Ships ESM + CJS with type declarations for both entry points.

### Patch Changes

- [#169](https://github.com/marco-lepore/yage/pull/169) [`fa3619e`](https://github.com/marco-lepore/yage/commit/fa3619e331be0841598c57bcf7bb385341b92663) Thanks [@marco-lepore](https://github.com/marco-lepore)! - Three fixes to the inventory addon:
  - `PointerInputBinding` skips clicks on consumed pointers. A tap another handler claimed via `InputManager.consumePointer` (e.g. a virtual-controls overlay) no longer also clicks the panel. The check runs at poll time, where the consume mark is still set regardless of listener registration order.
  - The unsubscribe returned by a filtered view's `on("changed")` is idempotent. Before, calling it twice drove the internal listener refcount negative, permanently detaching model forwarding for every later subscriber.
  - `InventoryChangedEvent` and `InventoryEvents.changed` docs state that `slots` is always empty when the source is a filtered view — a compacted projection has no stable slot indices to report. (The behavior is unchanged; the docs promised affected indices they never delivered.)
