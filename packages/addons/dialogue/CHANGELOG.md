# @yagejs-addons/dialogue

## 0.2.0

### Minor Changes

- [#122](https://github.com/marco-lepore/yage/pull/122) [`664748f`](https://github.com/marco-lepore/yage/commit/664748fdf3c6a9527981746d0c5bd2528db4402d) Thanks [@marco-lepore](https://github.com/marco-lepore)! - Add `@yagejs-addons/dialogue`, the first YAGE addon: a self-contained, themeable dialogue system.
  - **Headless core** (root entry `.`): runner/session/types, markup parser, i18n, canonical format, `DialogueController`, events, and pixi-free input bindings over `@yagejs/input`. The root entry never transitively imports `pixi.js` or `@yagejs/renderer`.
  - **Game-state via `VariableStorage`**: the bridge between a game and a conversation is installed once on the controller (`storage`, `functions`, `commands`); `play(script)` is content-only, with optional per-call overrides. Variables live in one opaque namespace backed by a Yarn-shaped `VariableStorage` (ships `MemoryVariableStorage` + `cells` two-way accessors + `compose`), persist across plays, and are seeded from a script's `declare` defaults only when absent (a game-linked value always wins). Conditions and `set` values are expression trees (`literal | varRef | call | unary | binary | group`, Yarn-modeled operators) so `gold - 50` and `has_item("key") and not rude` are plain data; `functions` supply argument-capable reads. Commands handle game mutations (`commands` map + optional `fallbackCommand`, still mirrored to `DialogueCommandEvent`); `set` / `ctx.setVar` / `handle.setVar` write through the storage (a read-only cell rejects the write — `handle.setVar` throws to the caller, while a script `set` is logged via the engine logger and ignored so it can't wedge the conversation). `defineScript()` infers variable types so `play()` returns a typed `DialogueHandle` (`setVar` / `getVars`); `DialogueController<TStorage>` is generic over its storage. Validated at load-time (references/types) and play-time (storage/functions/commands coverage), throwing `DialogueScriptError` / `DialoguePlayError`. (Replaces the earlier `params` + `onCommand` controller options.)
  - **String, YAML & compact authoring** (`parseExpr` + `./yaml` subpath + compact DSL): conditions and `set` values can be written as **strings** (`condition: "gold >= 50 and has_item('key')"`, `value: "gold - 50"`) instead of hand-built trees. A new pixi-free `parseExpr(src): Expr` (root entry) is a Pratt parser emitting the existing `Expr` union (no new node kinds) — `or/|| and/&& not/!`, the comparisons with Yarn word forms (`eq/neq/gt/lt/gte/lte/is`), unary `-`, binary `+ -`, calls, and parens (`xor/^` and `* / %` reserved but unwired); identifiers include `.`/`$` (so `$gold`/`quest.stage` are one name) but exclude `-` (so `hp-1` is a subtraction). `loadScript` (every loader, JSON included) resolves **all** string conditions and string `set` values to `Expr` in one pre-walk before freezing, so a bare name stays a truthy read (back-compat) while operator strings that used to silently fail now work; a small reserved-word set (`and or not xor is eq neq gt lt gte lte true false null`) can't be used bare. `parseExpr` throws `DialogueExprError` (with `line`/`col`); load-time validation now applies the same wrong-type-operand / numeric-op-vs-declared-non-number checks to parsed expressions that the atomic `{ var, op, value }` form already gave. **`loadYaml(text)`** (from the `@yagejs-addons/dialogue/yaml` subpath) parses a YAML document mirroring the JSON `DialogueScript` through the same loader (non-mapping roots rejected with a YAML-specific error). `yaml` is the addon's first runtime dependency (not a peer; out of the engine `fixed` changeset group) and is reachable only via the `./yaml` subpath, so JSON / TypeScript / expression authors never bundle the parser. A line-oriented **compact DSL** for RPG-style branching — `parseCompact(text)` / `loadCompact(text)`, on the **root** entry (no `yaml` dep) — compiles a script of one-statement-per-line leaders (`# id`, `@ id Name [#hex]` speakers, `:: node`, `speaker[ face]: text` with narrator fallback, coalesced `? text [if: cond] [-> target] #once #disabled #key:value` choices, `set v = rhs`, `do type k=v #flag` commands, `-> goto`, `end`) to the same IR through `loadScript`. Conditions and non-literal `set` values go through `parseExpr`; per-line `view=`/`voice=`/`speed=`/`auto=` set the first-class say fields and trailing `#key:value` hashtags become `meta` (Yarn-aligned); choice attributes use non-bracket sigils so inline `[..]` markup is passed through untouched (a `[..]` in a choice is inline markup — a built-in style or an effect span — and only a malformed built-in tag the parser can't act on is a load error).
  - **Presenters** (`./presenters` subpath): all pixi-backed rendering — Graphics chrome + canvas `SplitText`/`Text` views, avatars, composites, and factories. Zero bundled assets.
  - **Zero-config `defaultTheme()`**: Graphics chrome + canvas font with native bold/italic and per-glyph effects. Bitmap fonts are an opt-in theme path (one `bitmapFont` atlas; bold/italic are synthesised, so there are no variant-atlas theme fields).
  - **Exhaustive, textured theme surface**: every look-and-feel constant a default presenter reads is a `DialogueTheme` field — frame/text/choice colours and sizes, plus `caret` (blink + size), `choiceGap`, and the bubble `tailLean` — and each presenter-config field is named identically to the theme field it comes from, so re-skinning is mechanical (a test asserts every theme field reaches a presenter). `theme.textured` is a **map of named nine-slice chrome styles** (`{ frame: { texture, insets }, bubble? }`) rendered through the renderer's `createNineSlice`, so the addon keeps its zero-`pixi.js`-peer footprint. A box line chooses its frame per line via `meta.chrome`: a named style, the built-in `"none"` (no frame, for a full-bleed line), or — when it names none/an unknown one — the `"default"` style if present, else the drawn Graphics frame; the speech bubble renders the `"default"` style's `bubble`, content-sized per line. The default box choice list is content-driven — labels word-wrap and rows grow upward from the box's bottom edge to fit long or overflowing menus (a list too tall for the screen spills off the top non-overlapping), with one geometry pass shared by row placement, the selection highlight, and pointer hit-testing, plus a soft-cap advisory past `softMaxChoices`.
  - **Content-sized speech bubbles**: `BubbleChrome` grows to fit its wrapped text (via the renderer's `measureWrappedText`) instead of clipping at a fixed height — for bitmap fonts too, which size through the same width-first wrap-aware path as canvas text.
  - **VN controls**: session-level auto-advance (`setAutoAdvance(ms | null)`) and a hold-to-confirm skip (`fullControls(choices, { skipHoldMs })`), on top of the existing hold-to-fast-forward.
  - **Choice presentation — disabled options & timed choices**: a `ChoiceOption` can set `presentation: "disabled"` (default `"hidden"`) to keep a condition-failed option on screen greyed-out and non-selectable instead of filtering it (the Disco-Elysium "[Strength 8] Force the door" pattern), with an optional i18n-resolved `disabledReason`. `PresentedChoice` carries `disabled`/`disabledReason`; selection nav and pointer hover skip disabled rows (a multi-row skip fires one `DialogueSelectionChangedEvent` for the landed row), `confirm`/`choose`/pointer-commit refuse them, a step with zero _enabled_ options is skipped (no soft-lock), and a spent `once` option stays hidden regardless of presentation. The default list/bubble presenters grey disabled rows and append the reason; the radial wheel greys without a reason. Timed choices ship as a documented **recipe**, not a model feature: a non-blocking `choice-timer` command before the choice plus a host-owned timer (on the game's own clock) that calls `controller.choose(default)` on expiry, cancelling/re-arming on `DialogueChoiceShownEvent` to defuse a dangling timer; `ChoiceContext` now passes the choice step's `meta` through so a custom presenter can render a countdown from `meta.timeoutMs`.
  - **Lifecycle, visibility & events**: three orthogonal host levers — `setHidden(bool)` (visual-only cutscene takeover, state-preserving, persists across `stop()`/`play()`), `setPaused(bool)` (freezes the update loop + input without losing state or blocking host-driven `setVar`), and `setInputEnabled(bool)` (input focus — an unfocused conversation stays alive but consumes no device input, so the multi-instance "two conversations, one interactive" story is a one-liner). Visibility is now a first-class channel verb (`setVisible`) on every channel rather than a covert `setNameplate(undefined)` overload; a composite chrome restores its **active** variant on show (a hide/restore mid-bubble-line brings back the bubble + caret, not an empty box frame). Missing-actor/narrator lines no longer render invisibly at world origin: a speakerless line routes to the box (narrator convention) or a configurable fallback anchor, a despawned actor falls back to its last-known position, the line stays visible with its continue caret, and a dev warning routes through the engine `Logger`. Four new observation events — `DialogueRevealCompletedEvent`, `DialogueSelectionChangedEvent`, `DialogueSkipUsedEvent`, `DialogueAutoAdvanceEvent` — bubble entity → scene alongside the existing six; the reveal-completed seam is session-owned (no clobberable public field).
  - **Presenter contract & per-line layout**: writing a custom presenter is a documented contract instead of a reverse-engineering exercise. The typewriter clock is extracted into a headless, pixi-free **`LineReveal`** (root entry) — grapheme cursor, `[pause]` timing, per-run/line `[speed]`, hold multiplier, fired-once completion — so a DOM / per-word / accessibility text presenter reuses reveal timing without re-implementing it (`DialogueTextView` consumes it and keeps only the pixi-`SplitText` glyph mapping). The channel call-order invariants (chrome before text, geometry before present, reveal-completion exactly once via the session-owned seam) are JSDoc on the channel interfaces, with a "writing a custom presenter" section on both doc surfaces. Each coordinate model gets a single **layout owner** behind `./presenters`: `BubbleLayout` (one bubble measurement + the shared missing-actor anchor + the origin formula, replacing three drifting copies) and `BoxLayout` (the box frame rect + text region as one source). The box is now **viewport-relative** — `theme.box` is `{ marginX, marginY, height }` (virtual px) resolved against the renderer's design size at mount into a full-width bottom bar, so the **default presenter works at any resolution with no override**. Built on it: per-line **`meta.position`** (`top | center | bottom`) moves the box frame and body text together (reusing the box margins); box choices grow the frame, nameplate, prompt, and rows as **one panel** (capped at the screen); and an **inset registry** lets an in-box presenter reserve a column the body text reflows around. Composite **routing** is injectable — `createMixedDialogue(theme, { route })`, default speaker-aware (narrator → box; `view` wins; registered actor → bubble; else box), all three composites sharing the one route. **`AvatarChannel.present(line)`** (mirrors the chrome hook) makes avatars line-driven, and the avatar channel becomes composable like the others (`CompositeAvatarPresenter` routes box-vs-bubble on the shared route). Two shipped references, built only from the public contract: **`InBoxAvatarPresenter`** reads `meta.portrait` / `meta.side` / `meta.presence` and reflows the box body text **and choice rows** around an optional framed portrait (inset from the border); **`BubbleAvatarPresenter`** reserves a portrait column **inside** the speech bubble (`BubbleLayout.setPortraitInset`) so the bubble — and a bubble choice panel — grows and its text/options reflow around the portrait. Both take an `align: "top" | "center"` (default `center`). `createMixedDialogue(theme, { avatar: { box, bubble } })` wires each side and composes them; `createBoxDialogue` takes the box avatar directly. (Breaking: `theme.box` is reshaped from absolute `{ x, y, width, height }` to viewport-relative `{ marginX, marginY, height }` (`BoxRect` → `BoxBounds`); `BubbleChromeConfig`/`BubbleChoiceConfig` drop their mirrored sizing/anchor metrics, `DialogueChromeConfig`/`ChoiceListConfig` drop `box`/`padding`, the bubble text view drops `BubbleTextLayout`, and the composites take a richer `route`.)
  - **Extensible channels + built-in voice-over**: beyond the typed presenter trio, a host can **register** an open-ended `DialogueExtraChannel` (root entry, pixi-free) on a running conversation — voice-over, a shop reacting to a `buy` command, a camera-shake, a history recorder — so a game adds new conversation-driven behavior with zero addon change. Every method is optional (`present` / `revealComplete` / `command` / `clear` / `setVisible` / `setPaused` / `completeReveal` / `update` / `dispose` / `isRevealComplete`); `controller.addChannel(ch)` (or a `channels: []` ctor array, or `session.addChannel`) mounts a scene-needing channel (one that also implements the now root-exported `Mountable`), wires it into the session's cross-cutting stream, and returns a disposer; a registered channel catches up the `setVisible`/`setPaused` levers only (no `present` replay). A throwing channel hook is routed to the session `onError`, never breaking the conversation (the trio stays trusted). Auto-advance now gates on **text AND every registered gater**: the clock is armed when the text reveal completes but only counts down once every channel's `isRevealComplete()` is true, so a line auto-advances at `max(clipEnd, revealEnd)` with no duration plumbing (a manual advance is never gated; a channel without the method never blocks). Voice-over ships as **`createVoiceChannel({ play, onSkip?, pauseWithConversation?, livenessMs?, onError? })`** — the addon owns no audio, so the host wires `play(id, onEnded) => { stop, pause?, resume? }` over `@yagejs/audio`; it reads `PresentedLine.voice`, gates auto-advance on the clip, pauses with the conversation by default, and is hardened with a generation guard (a late `onEnded` from a superseded clip can't ungate the next line) and an optional liveness cap (a wedged host can't soft-lock auto-advance). Consequences-out holds — a channel mutates game state via `ctx.setVar` and reads it back through `handle.getVars()`, never the session.
  - **Reveal-driven events — per-grapheme ticks & inline markers, one ordered token stream**: the `LineReveal` clock emits a `RevealBeat` stream as a line types. Inline timeline controls are **self-closing tokens** sharing one ordered array — `ParsedText.tokens: readonly RevealToken[]` (each `{ kind: "pause" | "marker", atChar, … }`), replacing the separate `pauses`/`markers` arrays — so **source order is drain order**: `[pause=600/][shake/]` holds then fires; `[shake/][pause=600/]` fires then holds. `[pause=600/]` is now the only pause spelling (a bare `[pause=600]` without the slash opens an ordinary effect span named `pause`, not a hold); a `[name k=v/]` marker (`MarkerToken { kind, atChar, name, props }`) fires a reveal event at its char offset, surfaced as `DialogueRevealMarkerEvent` (`{ marker, viaSkip }`) on the entity bus. The self-named shortcut `[name=val/]` ≡ `[name name=val/]` (Yarn), so it composes with explicit props: `[shake=500 amount=3/]` → `{ shake: "500", amount: "3" }` (values can't contain whitespace or `/`). The **effect + hold** idiom falls out of the two orthogonal primitives — `[shake=500/][pause=500/]` fires the marker, then holds 500ms while the host plays it (no combined sugar; markers are non-blocking). Per-grapheme **ticks** surface as a direct `onRevealTick(index)` controller callback (raw index incl. whitespace — not an entity event; it fires hundreds of times per line) for a typewriter SFX. A skip/complete drains pending markers in order (`viaSkip: true`, so consequences still fire) and blows through pending pauses, but discards pending ticks (no machine-gun of blips); a marker-only / length-0 line drains at line start. The addon **name-matches no marker**: the avatar channel interprets `[expression=…/]` itself (the bundled portrait/scene presenters call their own `setExpression`, so a mid-line face change is zero-config), and every other name flows opaquely to the host. A registered `DialogueExtraChannel` sees the whole stream via the optional `revealBeat?(beat)` hook, and a custom text presenter forwards beats off `LineReveal` via `setBeatListener`. **The `expression` command was removed** — a mid-line face change is the `[expression=…/]` marker, and the line-initial face stays `SayStep.expression`; `set` is now the only built-in command.
  - **Inline text effects are an open vocabulary**: `RunStyle.effect` is an open `string` (the closed `EffectId` union is gone; `BuiltinEffectId` documents the four bundled effects `wave`/`shake`/`pulse`/`rainbow`), and any paired `[name]…[/name]` markup tag opens an effect span carrying that name — so `[glitch]…[/glitch]` parses to a run with `effect: "glitch"`. The bundled text presenter animates the four built-ins; a custom text channel can animate any name, and a presenter that doesn't recognize an effect renders the run as plain styled text — so a custom text channel adds effect tags with no addon change. The parser no longer gates effect names, and the choice-attribute guard only flags a built-in styling tag whose argument can't parse. (Only the type + parser are opened here; a register-your-own-effect presenter API is deferred — additive on top of the now-`string` field, whereas widening a published `EffectId` later would be breaking.)
  - **Grapheme-correct reveal**: every character count (run lengths, token offsets, per-glyph styles, `charsPerSec`) is in graphemes via `Intl.Segmenter` — the same segmentation pixi's `SplitText` renders one glyph per — so emoji, ZWJ sequences, and combining marks stay aligned during the typewriter reveal. `splitGraphemes()` is exported from the root entry.
  - **Opt-in `@experimental` radial choice presenter** under `./presenters`.

  Independently versioned (not part of the `@yagejs/*` fixed group). Ships ESM + CJS with type declarations for both entry points.
