`@yagejs-addons/behaviors` is movement-level AI: the logic that turns "chase
the player", "keep your distance", or "flock with your neighbors" into a
velocity every frame. It computes; your game applies. There's no pixi, no
physics, and no input in its dependency closure — the single most decoupled
addon in the toolkit.

<Aside type="note">
This is steering, not decision-making. It answers "which way do I move right
now", not "should I attack or flee". A behavior tree or state machine for the
decision layer is a separate, future addon that would sit above this one.
</Aside>

## Install

```bash
npm install @yagejs-addons/behaviors
# engine peer (single install, reused — not bundled):
npm install @yagejs/core
```

`@yagejs/core` is the only peer. One entry point — `@yagejs-addons/behaviors`
— there's no `/presenters` subpath, because steering has no view to swap.

## Zero-config kinematic chase

The default `apply` integrates the entity's `Transform` directly — no
physics body, no extra wiring:

```ts
import { SteeringAgent, seek } from "@yagejs-addons/behaviors";
import { Transform } from "@yagejs/core";

// enemy is an Entity with a Transform. Default apply:
// position += velocity * dt. Nothing else to wire.
enemy.add(
  new SteeringAgent({
    maxSpeed: 120,
    behaviors: [seek(() => player.get(Transform).position)],
  }),
);
```

`SteeringAgent` is a `@yagejs/core` Component: `ComponentUpdateSystem` drives
its `update(dt)` automatically once it's added to an entity. It assumes the
entity is root-level — the default apply writes `transform.position`
(local), so local and world coordinates need to match, which only holds
without a parent.

## Driving a physics body

Steering never imports `@yagejs/physics`. When an entity has a
`RigidBodyComponent`, hand the commanded velocity to it with a one-line
`apply` callback — the game owns the physics, the addon stays physics-free:

```ts
import { SteeringAgent, arrive } from "@yagejs-addons/behaviors";
import { RigidBodyComponent } from "@yagejs/physics";

const body = enemy.get(RigidBodyComponent);
enemy.add(
  new SteeringAgent({
    maxSpeed: 120,
    maxAcceleration: 600, // px/s² turn-rate cap; omit = velocity snaps to desired
    behaviors: [arrive(() => waypoint, { slowRadius: 140 })],
    apply: (v) => body.setVelocity(v),
  }),
);
```

## Blending behaviors

`SteeringAgent` sums every behavior's contribution, each scaled by its
`weight` (default 1), then clamps the result to `maxSpeed`. Give the
dominant behavior a higher weight:

```ts
import { SteeringAgent, flee, wander } from "@yagejs-addons/behaviors";

enemy.add(
  new SteeringAgent({
    maxSpeed: 90,
    faceHeading: true, // rotate the Transform to face travel direction
    behaviors: [
      flee(() => player.get(Transform).position, { radius: 200, weight: 2 }),
      wander({ weight: 0.5 }),
    ],
  }),
);
```

## Obstacle avoidance and flocking

Obstacles and flock neighbors are **game-supplied arrays**, not physics
queries — this is what keeps `@yagejs/physics` off the addon's peer list.
Pass a plain list, or a `() => list` provider for a live one:

```ts
import { SteeringAgent, seek, avoidObstacles } from "@yagejs-addons/behaviors";

enemy.add(
  new SteeringAgent({
    maxSpeed: 120,
    behaviors: [
      seek(() => player.position),
      avoidObstacles(
        () => rocks.map((r) => ({ position: r.position, radius: r.radius })),
        { lookAhead: 80, weight: 3 }, // high weight so avoidance dominates
      ),
    ],
  }),
);
```

Flocking (boids) composes from three primitives — separation, alignment,
cohesion — each reading the same neighbor list:

```ts
import { SteeringAgent, separation, alignment, cohesion } from "@yagejs-addons/behaviors";

for (const boid of boids) {
  const neighbors = () =>
    boids.filter((b) => b !== boid).map((b) => ({ position: b.position, velocity: b.velocity }));
  boid.entity.add(
    new SteeringAgent({
      maxSpeed: 100,
      behaviors: [
        separation(neighbors, { radius: 30, weight: 1.5 }),
        alignment(neighbors, { radius: 60 }),
        cohesion(neighbors, { radius: 60, weight: 0.8 }),
      ],
    }),
  );
}
```

## Headless / manual drive

Skip the Component entirely and drive the `Steering` model yourself — your
own loop, your own integration:

```ts
import { Steering, seek } from "@yagejs-addons/behaviors";
import { Vec2 } from "@yagejs/core";

const steering = new Steering([seek(() => target)]);
let pos = new Vec2(0, 0);
let vel = Vec2.ZERO;
// each tick:
vel = steering.compute({ position: pos, velocity: vel, maxSpeed: 120 }, dt);
pos = pos.add(vel.scale(dt));
```

## Live escape hatches

The hosted model and last-commanded velocity are always readable and
mutable — nothing here is locked behind construction-time config:

```ts
agent.steering.add(flee(() => boss.position, { weight: 4 })); // add a behavior live
agent.maxSpeed = 200; // retune
agent.velocity; // Vec2, last commanded — draw a debug arrow with it
agent.stop(); // zero the velocity now
agent.enabled = false; // pause ticking without removing the component
```

## Behaviors reference

Every factory returns a `SteeringBehavior` and takes an options object with
at least `weight` (default 1). Targets, obstacles, and neighbors accept
either a static value or a `() => value` provider, resolved fresh each tick.

| Behavior | Signature | Notes |
|---|---|---|
| `seek` | `seek(target, opts?)` | Straight toward `target` at full speed. |
| `flee` | `flee(target, { radius? })` | Straight away; `radius` gates it to nearby threats only. |
| `arrive` | `arrive(target, { slowRadius?, arriveRadius?, onArrive?, onDepart? })` | Ramps speed down inside `slowRadius`, settles inside `arriveRadius`. |
| `wander` | `wander({ distance?, radius?, jitter?, random? })` | Slowly-turning circle ahead of the current heading. |
| `pursue` / `evade` | `pursue(target, { maxPrediction? })` | `target` is `{ position, velocity }`; leads the predicted position. |
| `avoidObstacles` | `avoidObstacles(obstacles, { lookAhead?, agentRadius? })` | Look-ahead ray; steers around the closest threat in its path. |
| `separation` / `alignment` / `cohesion` | `separation(neighbors, { radius? })` | The three boid rules; `neighbors` is `{ position, velocity }[]`. |

`arrive`'s `onArrive`/`onDepart` are the addon's one discrete consequence —
fire your own entity/bus event from inside them in a line, if the game wants
one:

```ts
arrive(waypoint, {
  onArrive: () => enemy.emit(new ReachedWaypointEvent()),
});
```

## Not in v1

Path-following (consuming a plain `Vec2[]` of waypoints — no dependency on a
pathfinding package), priority-arbitration blending (v1 is weighted-sum
only), a steering-force output model, and physics-backed obstacle/neighbor
discovery are deferred. The output stays plain numbers, so nothing here
blocks a game from building its own on top.
