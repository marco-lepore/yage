`@yagejs-addons/dialogue` is the first **YAGE addon**: an installable,
opinionated dialogue system. A headless branching runner drives a swappable,
themeable presentation layer, so you drop it into a scene, point it at a script,
and get a working typewriter box (or speech bubble) with branching choices and
inline markup — then re-theme or replace any piece without forking.

## Install

```bash
npm install @yagejs-addons/dialogue
```

The addon declares the engine packages as **peer dependencies**, so it reuses
your single engine install rather than duplicating it. Install the engine
yourself:

```bash
npm install @yagejs/core @yagejs/input @yagejs/renderer
```

- `@yagejs/core` and `@yagejs/input` are **required** peers — the headless runner
  and the `DialogueController` use them.
- `@yagejs/renderer` is the **optional** peer — only the `./presenters` subpath
  needs it (and it brings `pixi.js` transitively). Consuming only the headless runner? Skip
  them.

## Two entry points

The package is split so the headless path never pulls a renderer:

```ts
// Headless + input only — no pixi, fully unit-testable.
import { DialogueRunner, DialogueController } from "@yagejs-addons/dialogue";

// Pixi presentation — Graphics chrome + canvas text, themes, factories.
import { defaultTheme, createBoxDialogue } from "@yagejs-addons/dialogue/presenters";
```

| Entry          | Imports                          | Contains |
| -------------- | -------------------------------- | -------- |
| `.`            | `@yagejs/core`, `@yagejs/input`  | runner, session, types, markup, i18n, canonical format, events, `DialogueController`, input bindings |
| `./presenters` | + `@yagejs/renderer` (brings pixi)  | chrome, text views, composites, avatars, factories, `defaultTheme()`, textured nine-slice variants, radial (experimental) |

## Quick start

The default presenters are **zero-asset**: Graphics objects for the box frame
plus canvas `SplitText`/`Text` for the typewriter, with native bold/italic and
per-glyph effects. `defaultTheme()` gives you a working look with no bundled
files.

<Steps>

1. **Declare the dialogue layers on your scene.** They are screen-space and sit
   above the in-scene UI so a conversation overlays everything.

   ```ts
   import { Scene } from "@yagejs/core";
   import { DIALOGUE_LAYERS } from "@yagejs-addons/dialogue/presenters";

   class TalkScene extends Scene {
     readonly layers = [...DIALOGUE_LAYERS];
     // ...
   }
   ```

2. **Spawn a host entity and add the controller.** Spread a factory bundle into
   `DialogueController` and override any one piece.

   ```ts
   import { DialogueController, DialogueEndedEvent } from "@yagejs-addons/dialogue";
   import { createBoxDialogue } from "@yagejs-addons/dialogue/presenters";

   onEnter() {
     const host = this.spawn("dialogue");
     const dlg = host.add(new DialogueController({ ...createBoxDialogue() }));
     host.on(DialogueEndedEvent, () => host.destroy());
     dlg.play(script);
   }
   ```

3. **Author a script** (plain data — see below) and pass it to `play()`.

</Steps>

<Aside type="tip">
`createBoxDialogue()` defaults its theme to `defaultTheme()`. Pass a theme to
restyle: `createBoxDialogue(myTheme)`. For a diegetic look, use
`createBubbleDialogue(theme?, { worldLayer })`; to mix both per line, use
`createMixedDialogue(theme?, opts)`. Speech bubbles size to their text — they grow
**width first** (up to `maxWidth`), then wrap and grow height — so a long line
widens the bubble instead of clipping (configure `minWidth` / `maxWidth` / `height`
on the bubble geometry).
</Aside>

## Writing a script

Author scripts with **`defineScript()`** — an identity helper (no runtime cost)
that captures the script's var/external types so `play()` demands a matching
binding and hands back a typed handle. A plain `DialogueScript` literal still
works and is validated identically at runtime; the typing is the only thing you
give up. Both are JSON-able, so you can also load a script from disk.

```ts
import { defineScript } from "@yagejs-addons/dialogue";

const script = defineScript({
  id: "intro",
  start: "greeting",
  vars: { rude: false },              // dialogue vars — conversation-local, mutable
  external: { gold: "number" },        // externals — game state, read-only to the script
  speakers: {
    gwen: { id: "gwen", name: "Gwen", color: 0xffd866 },
  },
  nodes: {
    greeting: {
      id: "greeting",
      steps: [
        { kind: "say", speaker: "gwen", text: "Hello, [b]traveler[/b]. You carry {gold} gold." },
        {
          kind: "choice",
          text: "What do you say?",
          options: [
            { text: "Greet her back.", target: "friendly" },
            {
              text: "Walk off.",
              once: true,
              commands: [{ type: "set", var: "rude", value: true }],
            },
          ],
        },
      ],
    },
    friendly: {
      id: "friendly",
      steps: [{ kind: "say", text: "Safe travels." }, { kind: "end" }],
    },
  },
});
```

### vars vs external

Both share **one lookup namespace** — conditions, `{token}` interpolation, and
choice gates read across both — but they have different ownership:

| | `vars` | `external` |
| --- | --- | --- |
| Lifetime | the conversation (reset fresh each `play()`) | the game |
| Writable by the script? | yes — `set` / `ctx.setVar` / `handle.setVar` | **no** (read-only; mutate game state via a command) |
| Declared as | `name: defaultValue` (type inferred) | `name: "string" \| "number" \| "boolean"` |
| Supplied at `play()` | optional override (by value) | required — a constant or a live getter |

`{gold}` (and any condition on `gold`) resolves **when the line is presented**, so
an earlier command's effect shows up on a later line. Already-shown lines never
re-render, and a choice menu's conditions don't live-refresh while it's open.

### Validation

The script is checked in two stages, both throwing hard errors so typos die early
rather than silently mis-branching:

- **Load-time** (`defineScript` / `loadScript`, no binding needed): every
  condition `var`, `set` target, and default-locale `{token}` must resolve to a
  declared `vars`/`external`; `set` targets must be a `var`; numeric comparisons
  on a non-number operand are rejected. Throws `DialogueScriptError`.
- **Play-time** (when you call `play`): the binding must provide every external
  with the right type, and every command type the script uses must have a handler.
  Throws `DialogueBindingError`.

### Step kinds

| Kind      | Purpose |
| --------- | ------- |
| `say`     | A line spoken by an optional `speaker`. Supports markup, `speed`, `autoAdvanceMs`, `expression`, `commands`, `view`, `meta`, `voice`. |
| `choice`  | A branch with `options` (each: `text`, `target?`, `condition?`, `once?`, `commands?`, `meta?`) and an optional prompt `text`. |
| `command` | Fire commands without showing anything; optionally a conditional `goto` via `condition` + `target`. |
| `goto`    | Unconditional jump to another node. |
| `end`     | Ends the conversation. |

A **condition** is a var/external key (truthy check), a comparison
`{ var, op, value }` (`op` is one of `== != > >= < <= truthy falsy`), or — in
TypeScript only — a `(vars) => boolean` predicate (it receives the merged
vars+externals view).

## Inline markup

Markup is a small BBCode-ish syntax that nests, inherits down the stack, and
survives translation (translators keep the tags). Unknown tags are dropped
silently.

| Tag | Effect |
| --- | ------ |
| `[b]…[/b]` `[i]…[/i]` | bold / italic |
| `[color=#ffcc00]…[/color]` / `[color=gold]…` | colour (hex or named) |
| `[wave]` `[shake]` `[pulse]` `[rainbow]` | per-glyph animated effects |
| `[speed=2]…[/speed]` | reveal-speed multiplier for the span |
| `[pause=400]` | zero-width reveal pause, in ms |
| `\[` `\]` | a literal bracket |

`parseMarkup(str)` and `stripMarkup(str)` are exported for tooling.

Every character count in the parsed result — `ParsedText.length`,
`TextRun.graphemeCount`, a pause's `atChar`, and the `charsPerSec` reveal rate —
is in **graphemes** (user-perceived characters), not UTF-16 code units. An
emoji like 🔥, a ZWJ sequence like 👩‍🚀, or an accent composed with a combining
mark counts as one character, matching the glyphs the renderer actually draws,
so reveal timing and `[pause]` positions stay put in any language.
`splitGraphemes(str)` exposes the same segmentation for tooling.

## Game state: the binding

`play(script, binding)` is the single bridge between your game and a conversation
(it replaces the older `params` + `onCommand` options). The binding is required
whenever the script declares externals:

```ts
const handle = dlg.play(script, {
  state: {
    gold: () => player.gold,   // external getter — read live at present-time
    rude: false,               // optional: override a var's default by value
  },
  commands: {
    "give-item": (cmd) => inventory.add(cmd.id as string),
    "skill-check": async (cmd, ctx) => {
      ctx.setVar("passed", await roll(cmd.stat as string)); // result for THIS conversation
    },
  },
  fallbackCommand: (cmd) => log(cmd), // optional: catch dynamically-typed commands
});

handle.setVar("rude", true); // poke a dialogue var live (typed to keyof vars)
handle.getVars();            // read the current dialogue vars (externals excluded)
```

- **External getters must be cheap and side-effect-free** — they're called on
  every condition test and every line/choice presented.
- **`ctx.setVar(key, value)`** writes a *dialogue var* — the skill-check seam for
  a result that only matters to this conversation. Writing an external throws
  (game state is yours to mutate, via a command).
- A `DialogueController({ binding })` default merges *under* the per-`play()`
  binding (the call-site wins key-by-key) — handy for globals like
  `gold: () => player.gold` shared across every conversation.

After the conversation, the **handle** no-ops harmlessly (a stale `setVar` is
ignored; `getVars` returns an empty snapshot), so you can keep a reference past
`DialogueEndedEvent` without guarding it.

### Commands — rules in, consequences out

The runner owns one built-in command: `set`, which writes a dialogue var
(guarded — you can't `set` an external). **Every other command** dispatches to
your `binding.commands[type]` handler (or `fallbackCommand`) *and* fires a
`DialogueCommandEvent` for observation — so *the game* decides what `give-item`
or `play-sfx` actually mean.

- A `say` line's commands fire by timing: `at: "show"` (default), `"afterReveal"`
  (once typed), or `"advance"` (as the player leaves the line).
- A command with `blocking: true` whose handler returns a promise **pauses** the
  conversation until it resolves — for cinematic sequencing ("wait for the NPC to
  walk off, then continue").
- `{ type: "expression", value }` is a built-in convenience routed straight to
  the avatar (no handler needed).
- Every non-built-in command type a script uses must have a handler or a
  `fallbackCommand`, or `play()` throws — no command silently does nothing.

## Lifecycle events

The controller emits these from its host entity (they bubble entity → scene, so
a scene can listen with `this.on(...)`):

| Event | Payload |
| ----- | ------- |
| `DialogueStartedEvent` | `{ scriptId }` |
| `DialogueLineEvent` | `{ speaker?, text }` (plain, markup-stripped — handy for a backlog/a11y) |
| `DialogueChoiceShownEvent` | `{ options }` |
| `DialogueChoiceMadeEvent` | `{ index, text }` |
| `DialogueCommandEvent` | `{ command, mode }` |
| `DialogueEndedEvent` | `{ scriptId }` |

`DialogueController` is multi-instance friendly: several ambient conversations
can run at once. *Which one is interactive* and *whether the world pauses* are
your game's policy — there is no global singleton.

## Presenters & channels

The view splits into narrow **capability channels** — `TextChannel`,
`ChoiceChannel`, `AvatarChannel`, `ChromeChannel` — so the typewriter, choice UI,
portrait, and frame are each swappable and composable. Presenter adapters add the
YAGE lifecycle (`mount`/`dispose`) and pointer hit-test seams.

| Concern | Default (box) | Default (bubble) |
| ------- | ------------- | ---------------- |
| Chrome  | `DialogueChrome` | `BubbleChrome` |
| Text    | `DialogueTextView` | `BubbleTextView` |
| Choices | `ChoiceListPresenter` | `BubbleChoicePresenter` |

`createMixedDialogue` composes both behind `CompositeChrome` /
`CompositeTextPresenter` / `CompositeChoicePresenter`, routing each line and
choice to box or bubble by its `view` hint.

Avatars are decoupled too: `PortraitPresenter` (a sprite beside the box),
`SceneFigurePresenter` (an NPC already in the world), or `NullAvatarPresenter`.
A `DialogueActor` component on a world entity self-registers under a speaker id
(via `actorRegistryFor(scene)`) so a speech bubble can find and follow the
speaker's head anchor.

## Input

The controller attaches a `KeyboardInputBinding` by default. Swap or compose it:

```ts
import { fullControls } from "@yagejs-addons/dialogue";

new DialogueController({
  ...createBoxDialogue(),
  // choice presenter for pointer hit-testing; hold X ~600ms to skip
  input: fullControls(bundle.choices, { skipHoldMs: 600 }),
});
```

- `KeyboardInputBinding(actions?, skipHoldMs?)` — advance / hold-to-fast-forward
  / choice nav / skip. `skipHoldMs > 0` gives the classic **hold-to-confirm skip**
  (default `0` = fire on press).
- `PointerInputBinding(choiceTarget?)` — tap to advance; tap/hover choice rows.
- `CompositeInputBinding` / `fullControls(choiceTarget?, { actions?, skipHoldMs? })`
  — both at once.
- `DEFAULT_ACTIONS` / `FULL_ACTIONS` — action-map presets.

For a VN-style **auto-advance** toggle, call `controller.setAutoAdvance(ms)` (and
`setAutoAdvance(null)` to turn it off); a per-line `autoAdvanceMs` still overrides
it. An ambient (always auto-advancing) conversation simply attaches no binding.

## Theming

A `DialogueTheme` is one flat data object (geometry, colours, fonts, layers,
reveal rate). `defaultTheme()` returns a fresh zero-asset instance each call, so
spread-and-tweak is safe:

```ts
const theme = { ...defaultTheme(), textColor: 0xffe0c0, charsPerSec: 60 };
createBoxDialogue(theme);
```

    effects. Set `fontFamily` to choose the canvas font. No bundled files.

    chrome.
  </TabItem>
</Tabs>

## Experimental: radial choices

A Mass-Effect-style choice wheel ships under `./presenters` as
`RadialChoicePresenter`, marked **`@experimental`**. It proves the choice seam is
swappable, but it is not part of any default factory bundle and is intentionally
unpolished — its geometry and API may change. Opt in by constructing it yourself
and passing it as the `choices` channel.

## Save / load

<Aside type="caution" title="Deferred to v1.1">
Mid-dialogue **cursor** save/restore is **not supported yet**. Snapshot/restore
is not built, `@yagejs/save` is **not** a dependency, and the runner's positional
getters (`getNodeId()`, `getStepIndex()`, `getChosenOnce()`) are **not reachable**
through `DialogueController` / `DialogueSession` — there is no way to capture a
resumable conversation cursor from a game. (`handle.getVars()` *is* reachable, but
that's the dialogue-var snapshot, not a cursor.) The binding model makes the
eventual API purely additive — `handle.getCursor()` returning the mutable var map
plus `{ nodeId, stepIndex, chosenOnce }`, with externals excluded by construction
(your own save owns game state). Save outside conversations (or replay the script
on load) until v1.1 adds the seam.
</Aside>
