import { Aside } from "@astrojs/starlight/components";

`@yagejs-addons/synth` gives a game sound effects without any audio files. A
sound is a plain parameter object — an oscillator, a pitch glide, an envelope,
maybe a filter. The addon renders it to samples, wraps them in an
`AudioBuffer`, and registers it with `@yagejs/audio` under an alias, so it
plays through the engine's channels, volumes, mute, and blur auto-pause
exactly like a preloaded file.

It is worth reaching for when you want a jam-ready shoot/hit/pickup set
without sourcing audio, when a sound should be tweakable by editing a number,
or when tests need to assert on what a sound actually does.

## Install

```bash
npm install @yagejs-addons/synth
npm install @yagejs/core @yagejs/audio
```

Both peers are required — the addon registers its buffers through
`@yagejs/audio`. There is no `./presenters` subpath: nothing here draws.

## Five-minute setup

```ts yage-context="engine"
import { AudioPlugin, AudioManagerKey } from "@yagejs/audio";
import {
  SynthPlugin,
  synthPresets,
  synthVariantAliases,
} from "@yagejs-addons/synth";

engine.use(new AudioPlugin());
engine.use(
  new SynthPlugin({
    sounds: {
      explosion: synthPresets.explosion(),
      coin: synthPresets.coin(),
      // Four takes, spread in pitch, so repeated shots don't sound identical.
      shoot: { sound: synthPresets.shoot(), variants: 4 },
    },
  }),
);
```

Playing them is the normal audio API — from a Component, Entity, or Scene:

```ts yage-context="component"
import { AudioManagerKey } from "@yagejs/audio";
import { synthVariantAliases } from "@yagejs-addons/synth";

const audio = this.use(AudioManagerKey);

audio.play("explosion", { volume: 0.8 });
audio.playRandom(synthVariantAliases("shoot", 4));
```

<Aside type="note">
Sounds are rendered once, when the plugin installs. That needs no
`AudioContext`, so it happens before the browser's first-gesture unlock and
costs nothing at play time. `SynthPlugin` declares the audio plugin as a
dependency, so installing it without `AudioPlugin` throws instead of failing
silently.
</Aside>

## Presets

Each preset is a function returning patch data, and takes overrides — so a
different gun, a bigger explosion, or a wooden floor is one number away.

```ts
import { synthPresets } from "@yagejs-addons/synth";

synthPresets.shoot({ frequency: 900 });                    // higher-pitched
synthPresets.explosion({ frequency: 200, duration: 0.6 }); // bigger boom
synthPresets.footstep({ surface: "wood" });                // stone | wood | grass
synthPresets.victory({ noteDuration: 0.24 });              // slower fanfare
synthPresets.shoot({ gain: 0.5 });                         // half as loud
```

What you can override follows the shape of the sound, so a field the preset
cannot honour is a compile error rather than a line that quietly does
nothing:

- **One voice or layered** (shoot, hit, explosion, footstep, wind, …) takes
  patch fields — `frequency`, `duration`, `filter`, and the rest. On a layered
  preset they land on the lead voice, so the layers keep their relationship.
- **A note sequence** (pickup, coin, victory, defeat) takes its shared voice's
  fields plus `noteDuration` and `noteSpacing`. Pitch and length come from the
  notes, so `frequency`, `glideTo`, `duration`, `delay`, and `seamless` are
  rejected. `dialogueBeeps` is the exception: it generates its notes, so it
  adds a base `frequency` along with `count`, `spread`, and `phraseSeed`.
- **`gain` works on all of them**: it multiplies every voice's volume, which
  is what you want for making a whole layered sound quieter. `volume` sets a
  single voice's peak instead.

The full set: `shoot`, `hit`, `explosion`, `hurt`, `pickup`, `coin`, `jump`,
`land`, `dash`, `powerup`, `footstep`, `uiClick`, `uiBlip`, `alarm`,
`victory`, `defeat`, `roomTone`, `wind`, `dialogueBeeps`. Their levels are
tuned to sit next to each other; scale them with `gain` to taste.

Two of them are loops rather than one-shots. `wind` is an ambient bed with
gust swells baked inside the loop. `dialogueBeeps` is speech chatter for
text reveals — short blips around a base pitch with syllable-like rests:

```ts yage-context="engine"
import { SynthPlugin, synthPresets } from "@yagejs-addons/synth";

engine.use(
  new SynthPlugin({
    sounds: {
      "voice/guard": synthPresets.dialogueBeeps({
        frequency: 220,
        phraseSeed: 4,
      }),
    },
  }),
);
```

After initialization, play the configured sound from a component method:

```ts yage-context="component"
import { AudioManagerKey } from "@yagejs/audio";

const audio = this.use(AudioManagerKey);

const talking = audio.play("voice/guard", { loop: true, channel: "voice" });
audio.stop(talking); // when the line finishes revealing
```

The same `phraseSeed` always speaks the same phrase, so a character's voice is
stable across plays; a different `frequency` and `phraseSeed` gives each
character their own.

## Writing your own sound

A patch is one voice:

```ts
import type { SynthPatch } from "@yagejs-addons/synth";

const zap: SynthPatch = {
  wave: "square",      // sine | square | sawtooth | triangle | noise
  frequency: 1200,     // starting pitch
  glideTo: 200,        // pitch at the end — the exponential fall
  duration: 0.09,
  attack: 0.004,       // fade-in; the rest of the duration is the release
  curve: 4,            // release steepness
  volume: 0.2,
};
```

Add `noise: 0.4` to mix white noise into the tone, or a filter with an
optional sweep:

```ts
import type { SynthPatch } from "@yagejs-addons/synth";

const whoosh: SynthPatch = {
  wave: "noise",
  duration: 0.22,
  filter: { type: "bandpass", frequency: 500, sweepTo: 5200, q: 2 },
};
```

An array of patches plays as one sound, so layers stack — each voice can start
late:

```ts
import type { SynthPatch } from "@yagejs-addons/synth";

const shotgun: SynthPatch[] = [
  { wave: "sawtooth", frequency: 300, glideTo: 40, duration: 0.25, volume: 0.3 },
  { wave: "noise", duration: 0.3, volume: 0.3, filter: { type: "lowpass", frequency: 2000, sweepTo: 300 } },
  { wave: "square", frequency: 90, duration: 0.1, delay: 0.28, volume: 0.1 }, // the pump
];
```

And a jingle bakes a note sequence into a single buffer:

```ts
import type { SynthJingle } from "@yagejs-addons/synth";

const levelUp: SynthJingle = {
  notes: [523, 659, 784, 1046], // Hz; 0 is a rest
  noteDuration: 0.18,
  noteSpacing: 0.12,            // shorter than the notes, so they ring into each other
  voice: { wave: "triangle", volume: 0.26 },
};
```

Any sound shape — patch, patch array, jingle or instrument descriptor — goes
straight into `SynthPlugin`'s `sounds` config.

## Sounds you can test

`renderSynthPatch` turns a patch into a `Float32Array`. It is plain math: no
WebAudio, no randomness that isn't seeded, no engine involved. The same patch
always renders the same samples, so a sound can be checked in a unit test the
way any other pure function is.

```ts yage-context="vitest"
import { renderSynthPatch } from "@yagejs-addons/synth";

const samples = renderSynthPatch({ frequency: 800, glideTo: 100, duration: 0.4 });
expect(samples).toHaveLength(0.4 * 44100);
```

## Registering a sound outside the plugin config

`synthBuffer` renders straight to an `AudioBuffer` for sounds a game builds at
runtime — a boss whose hit sound tracks its remaining health, say:

```ts
import { registerSound, unregisterSound } from "@yagejs/audio";
import { synthBuffer, synthPresets } from "@yagejs-addons/synth";

registerSound("boss-hit", synthBuffer(synthPresets.hit({ frequency: 180 })));
// later
unregisterSound("boss-hit");
```

## Variation between plays

A rendered buffer sounds identical every time it plays. Two ways to break that
up:

```ts yage-context="engine"
import {
  SynthPlugin,
  synthPresets,
  synthVariantAliases,
} from "@yagejs-addons/synth";

// Several takes, picked at random per play.
engine.use(
  new SynthPlugin({
    sounds: {
      shoot: { sound: synthPresets.shoot(), variants: 4, detune: 0.08 },
    },
  }),
);
```

After initialization, play the configured sound from a component method:

```ts yage-context="component"
import { AudioManagerKey } from "@yagejs/audio";
import { synthVariantAliases } from "@yagejs-addons/synth";
import { RandomKey } from "@yagejs/core";

const audio = this.use(AudioManagerKey);
const random = this.use(RandomKey);

audio.playRandom(synthVariantAliases("shoot", 4));

// Or jitter the playback rate at the call site, with the scene's random
// generator. Variants register only the suffixed aliases, so play one of those.
audio.play("shoot.1", { speed: random.range(0.95, 1.05) });
```

A `variants: n` entry registers `alias.1` … `alias.n` — nothing under the bare
alias — spread evenly across ±`detune` (default ±6%), each with its own noise.

## Ambient loops

`seamless: true` drops the envelope and crossfades the end of the buffer into
its start, so it loops without a click. The crossfade consumes up to 50 ms, so
the buffer comes out slightly shorter than `duration` — don't schedule
anything against the exact requested length:

```ts yage-context="engine"
import { SynthPlugin, synthPresets } from "@yagejs-addons/synth";

engine.use(
  new SynthPlugin({
    sounds: { ambience: synthPresets.roomTone({ duration: 6 }) },
  }),
);
```

After initialization, play the configured sound from a component method:

```ts yage-context="component"
import { AudioManagerKey } from "@yagejs/audio";

const audio = this.use(AudioManagerKey);

audio.play("ambience", { loop: true, channel: "music" });
```

## Save and load

Nothing to persist. The plugin re-registers every sound from its config on
each boot, so a snapshot only ever holds the alias string — the same contract
as runtime textures. `plugin.aliases` lists what it registered, and
`onDestroy` gives them back.

## Instruments and sustain regions

Import instruments by name from `@yagejs-addons/synth/instruments`. An
ESM bundle keeps only the instruments it imports. A `require()` of
`@yagejs-addons/synth/instruments` loads all 25 instruments, because
CommonJS cannot drop unused exports.
Each definition provides `sound(options?)` for a portable descriptor and
`render(options?, sampleRate?)` for samples with optional sustain points.
Pass the definitions used by your sounds to `SynthPlugin.instruments`:

```ts yage-context="engine"
import { AudioPlugin } from "@yagejs/audio";
import { SynthPlugin } from "@yagejs-addons/synth";
import { bass, electricPiano, flute } from "@yagejs-addons/synth/instruments";

engine.use(new AudioPlugin());
engine.use(new SynthPlugin({
  instruments: { electricPiano, bass, flute },
  sounds: {
    keys: electricPiano.sound(),
    bass: bass.sound({ frequency: 130.812783 }),
    lead: flute.sound({ seed: 42, volume: 0.15 }),
  },
}));
```

Available names: banjo, bass, uprightBass, guzheng, marimba, kalimba,
glassBell, vibraphone, bell, electricPiano, pad, flute, clarinet, organ,
kick, brushTap, brushSwish, shaker, rim, clap, ride, cymbal, tom,
pinkNoise and brownNoise. `synthInstruments` from
`@yagejs-addons/synth/instruments` contains every definition when the
application needs the complete catalogue.

Options are `frequency` (default 261.625565 Hz), `seed` (default 1), and
`volume` (default 0.3). Drums and noise ignore pitch, and their definitions
have `pitched: false`. A pitched instrument's sample reports `rootNote`, the
MIDI pitch of its frequency (440 Hz is 69). The tom sounds at a fixed pitch and
reports `rootNote` 43. Rendering accepts sample rates
8000–96000 Hz, frequency 20–min(4000, sampleRate/4) Hz, volume 0–1, and
uint32 seeds.

```ts
import { flute } from "@yagejs-addons/synth/instruments";
const sample = flute.render({ frequency: 440, seed: 17 }, 44100);
console.log(sample.samples.length, sample.loopStart, sample.loopEnd);
console.log(sample.rootNote); // 69
```

`renderSynthSample(sound, sampleRate?, instruments?)` renders a descriptor,
patch, patch array or jingle. The instrument set defaults to empty; an
instrument absent from that set throws naming the instrument. The same
third argument applies to `renderSynthInstrument`, `renderSynthSound` and
`synthBuffer`. Patches and jingles need no instrument set.

`sampleBuffer(sample)` creates an AudioBuffer. Pad, flute, clarinet, organ
and noise samples include sustain regions in seconds. SynthPlugin registers
each sample's sustain region and root note with its alias, so the music addon
transposes notes without a `rootNote` in the song. With manual registration,
pass them to `registerSound(alias, buffer, { loopStart, loopEnd, rootNote })`.
`renderSynthSound` and `synthBuffer` omit loop metadata; use
`renderSynthSample` when you need it. Play sustained instruments with
`loop: true` and stop them with `handle.release({ at, duration })`.

## Writing your own instrument

An instrument is a function that renders one note. `defineInstrument` gives it
a name, and the result works everywhere a built-in instrument does: in
`SynthPlugin`, in a worker, as a [music](/addons/music/) track source and in
the [audio build tool](/tooling/audio/). Keep instruments in their own module
and import from `@yagejs-addons/synth/render`, which loads in the browser, in a
module worker and in Node:

```ts yage-group="custom-instrument" yage-file="instruments.ts"
import {
  biquad,
  defineInstrument,
  limit,
  normalize,
  renderMetal,
  renderString,
} from "@yagejs-addons/synth/render";

/** A harp: a bright string plucked near the middle. */
export const harp = defineInstrument("harp", (frequency, sampleRate, seed) => {
  const t60 = Math.min(3, Math.max(1, 3 - (frequency - 200) / 500));
  const out = renderString(
    {
      frequency,
      duration: t60 + 0.2,
      t60,
      brightness: 0.7,
      pickPosition: 0.4,
      seed,
    },
    sampleRate,
  );
  biquad(out, "highpass", 80, 0.7, sampleRate);
  return limit(normalize(out, 0.9));
});

/** A closed hi-hat. It ignores the frequency, so it has no root note. */
export const hat = defineInstrument(
  "hat",
  (_frequency, sampleRate, seed) => {
    const out = renderMetal(
      { duration: 0.12, t60: 0.05, frequencyScale: 1.9, seed },
      sampleRate,
    );
    biquad(out, "highpass", 7000, 0.7, sampleRate);
    return limit(normalize(out, 0.9));
  },
  { pitched: false },
);
```

The render function receives the note's frequency in Hz, the sample rate and a
uint32 seed, and returns a `Float32Array`. A sustained instrument returns
`{ samples, loopStart, loopEnd }` with the loop in sample indices;
`prepareTonalLoop` finds a seamless loop end for a pitched tone. Finish with
`limit(normalize(out, 0.9))` like the built-ins do, so the sample peaks at about
0.87 before `volume` applies. Return a new buffer on every call: the definition
checks the options and the loop, multiplies the samples by `volume` (default
0.3) in place, converts the loop to seconds and, unless `pitched: false`,
reports the MIDI note of the frequency as `rootNote`. Take every random choice
from `seededRandom(seed)`, so a descriptor renders the same samples in the
browser, a worker and the build.

A drum that ignores the frequency but sounds at a known pitch also sets that
pitch as `rootNote`. The built-in tom uses `{ pitched: false, rootNote: 43 }`,
so a music track transposes it from G2.

Pass the definitions to the plugin with the built-ins you use:

```ts yage-group="custom-instrument" yage-context="engine"
import { AudioPlugin } from "@yagejs/audio";
import { SynthPlugin } from "@yagejs-addons/synth";
import { flute } from "@yagejs-addons/synth/instruments";
import { harp, hat } from "./instruments.js";

engine.use(new AudioPlugin());
engine.use(
  new SynthPlugin({
    instruments: { flute, harp, hat },
    sounds: {
      pluck: harp.sound({ frequency: 220 }),
      tick: hat.sound(),
      lead: flute.sound(),
    },
  }),
);
```

`harp.sound()` returns a descriptor typed to the name `"harp"`. With
`instruments` written inline, a sound that names an instrument outside it is a
type error. A game that builds `sounds` from data types the set as
`SynthInstrumentBank`, and the plugin checks the names when it installs. A
worker imports the same module and calls `serveSynthWorker({ flute, harp, hat })`.
The `pluck` alias carries its root note, so a music track plays it in tune.

The building blocks, all exported from `@yagejs-addons/synth/render`:

| Function | Renders or does |
| --- | --- |
| `renderString(options, sampleRate)` | A plucked string: brightness, pick position, decay, vibrato |
| `renderModal(options, sampleRate)` | A struck object from decaying partials: bells, mallets, gongs |
| `renderAdditive(options, sampleRate)` | A sustained tone from harmonic weights, with a sustain loop |
| `renderMetal(options, sampleRate)` | Metallic noise for cymbals and hi-hats |
| `renderNoise(options, sampleRate)` | White, pink or brown noise. With `loop: true`, return it as `{ samples, loopStart: 0, loopEnd: samples.length }` |
| `biquad(buffer, type, frequency, q, sampleRate, gainDb?)` | Lowpass, highpass, bandpass, peaking, shelf or notch filter |
| `svf(buffer, mode, frequency, q, sampleRate)` | A filter whose cutoff can follow a function of time, for sweeps |
| `normalize`, `limit`, `saturate`, `dcBlock`, `fadeIn`, `fadeOut` | Level, drive and edges |
| `prepareTonalLoop(buffer, sampleRate, loopStart, approxEnd, frequency, crossfade)` | A phase-matched sustain loop end |
| `seededRandom(seed)` | The seeded generator every built-in uses |

The five `render…` functions allocate new samples, and `renderAdditive` returns
them with loop points. Each throws when the sample rate, the duration or a top-level
`frequency`, `t60` or `frequencyScale` option is zero, negative or not finite. `renderAdditive` also requires the
ranges an instrument accepts. The filters and the level and edge functions
change the buffer they receive and return it. `fadeIn` and
`fadeOut` take their length in samples. `prepareTonalLoop` crossfades the
buffer in place and returns the loop end. `seededRandom` returns a function
that yields numbers in [0, 1).

## Worker rendering and readiness

For a large bank, provide a dedicated module worker. Import the same
instrument definitions in the worker and the plugin so main-thread fallback
can render every sound. An empty set supports patches and jingles only:


```ts
import { serveSynthWorker } from "@yagejs-addons/synth/worker";
import { flute } from "@yagejs-addons/synth/instruments";
serveSynthWorker({ flute });
```

Pass `worker: new Worker(new URL("./synth-worker.ts", import.meta.url), { type: "module" })` to SynthPlugin in a bundler that supports module workers.
The plugin owns and terminates that worker. Engine startup awaits the complete
bank; play sources only after startup. With no worker, it renders on the main
thread using the same seeded functions.

`plugin.getDiagnostics()` reports state, mode, completed/total, fallbackReason
and failure. Worker transport errors or inactivity (default `workerTimeout: 5000` ms) fall back to main-thread rendering with an explicit reason. Invalid
sound data rejects installation. Destruction cancels pending work and removes
registered aliases. A disposed plugin cannot be installed again.

## Build-time rendering and portable sound data

Use `@yagejs-tools/audio` to export selected sounds as WAV files before the
game starts. The game can then load the bank through `@yagejs/audio` without
importing the synth catalogue. See [audio builds](https://yage.dev/tooling/audio/).

The `/render` entry works in Node and browser previews without an AudioContext:

```ts
import { parseSynthSound, renderSynthSample } from "@yagejs-addons/synth/render";
import { flute } from "@yagejs-addons/synth/instruments";
const instruments = { flute };
const descriptor = parseSynthSound({ instrument: "flute", seed: 17 }, instruments);
const sample = renderSynthSample(descriptor, 44100, instruments);
console.log(sample.samples.length, sample.loopStart, sample.loopEnd);
```

`parseSynthSound(unknown, instruments?)` validates and copies portable instrument, patch,
layer and jingle data. Instrument names must be present in the supplied set.
Unknown fields throw. Portable data limits duration
and delay to 30 seconds each, layers to 32 patches, and jingles to 256 notes
within 60 seconds. Volumes are 0–1 and seeds are uint32.

Flute and clarinet combine authored harmonic spectra with breath noise and
pitch motion. Organ combines harmonic oscillators. All three include a
sustain region and use the package's MIT license.
