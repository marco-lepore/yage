title: "State Management"
description: "Game state with DI services, reactive stores, and event-driven patterns"
---

YAGE provides several ways to manage game state depending on your needs:
DI-registered services for shared state, reactive stores for UI binding, and
events for decoupled communication.

## Service Key Pattern

The most common approach is a plain class registered as a DI service:

```typescript yage-group="service-state"
import { Component, Scene, ServiceKey } from "@yagejs/core";

interface GameState {
  score: number;
  health: number;
  level: number;
}

const GameStateKey = new ServiceKey<GameState>("gameState");
```

Register it in your scene:

```typescript yage-group="service-state"
class GameScene extends Scene {
  readonly name = "game";
  onEnter(): void {
    const state: GameState = { score: 0, health: 100, level: 1 };
    this.context.register(GameStateKey, state);
  }
}
```

Access it from any component or system in the scene:

```typescript yage-group="service-state"
class ScoreDisplay extends Component {
  private readonly state = this.use(GameStateKey);

  update(): void {
    this.state.score; // read
  }
}
```

This pattern is simple and type-safe. If the service needs to persist, include
its durable fields in an explicit `Serializable<TEncoded>` save root.

## Reactive Stores (for React UI)

When bridging ECS state to React UI, use `createRecord`:

```typescript yage-group="react-store" yage-file="hud.tsx"
import { createRecord } from "@yagejs/core";

const uiStore = createRecord({
  default: () => ({
    score: 0,
    health: 100,
    message: "",
  }),
});
```

**Write from ECS** (systems, components, event handlers):

```typescript yage-group="react-store" yage-file="hud.tsx"
// In a component or event handler
uiStore.set({ score: uiStore.get().score + 10 });
```

**Read from React** (auto-rerenders on change):

```tsx yage-group="react-store" yage-file="hud.tsx"
import { Text, useStore } from "@yagejs/ui-react";

function HUD() {
  const score = useStore(uiStore, (src) => src.get().score);
  return <Text>{`Score: ${score}`}</Text>;
}
```

The store acts as a one-way bridge: ECS writes, React reads. This keeps
game logic in the ECS layer and rendering in the UI layer.

## Event-Driven State

For decoupled state changes, use typed events:

```typescript yage-group="events"
import { Component, Scene, createRecord, defineEvent } from "@yagejs/core";
import { ColliderComponent } from "@yagejs/physics";

const CoinCollected = defineEvent("coin:collected");
const PlayerDied = defineEvent("player:died");
const uiStore = createRecord({ default: () => ({ score: 0 }) });
```

**Emit from entities** (via entity events — bubble up to the scene):

```typescript yage-group="events"
// In a coin's trigger handler
class CollectCoin extends Component {
  onAdd(): void {
    this.sibling(ColliderComponent).onTrigger((ev) => {
      if (ev.entered) {
        this.entity.emit(CoinCollected);
        this.entity.destroy();
      }
    });
  }
}
```

**Listen at the scene level:**

```typescript yage-group="events"
class GameScene extends Scene {
  readonly name = "game";

  onEnter(): void {
    const state = { score: 0, health: 100 };

    this.on(CoinCollected, () => {
      state.score += 10;
      uiStore.set({ score: state.score });
    });

    this.on(PlayerDied, () => {
      state.health = 100;
      state.score = 0;
      // Reset player position...
    });
  }
}
```

This keeps entities decoupled — a coin doesn't need to know about the score
system, it just emits an event.

## Combining Patterns

A typical game combines all three:

```typescript
import { Scene, ServiceKey, createRecord, defineEvent } from "@yagejs/core";

interface GameState {
  score: number;
  health: number;
  level: number;
}

// 1. Game state as a DI service
const GameStateKey = new ServiceKey<GameState>("gameState");

// 2. UI store for React binding
const uiStore = createRecord({ default: () => ({ score: 0, health: 100 }) });

// 3. Events for decoupled communication
const CoinCollected = defineEvent("coin:collected");

class GameScene extends Scene {
  readonly name = "game";
  onEnter(): void {
    const state: GameState = { score: 0, health: 100, level: 1 };
    this.context.register(GameStateKey, state);

    this.on(CoinCollected, () => {
      state.score += 10;
      uiStore.set({ score: state.score });
    });
  }
}
```

- **ServiceKey** — source of truth, accessible from any component
- **Store** — React-friendly projection of the state
- **Events** — triggers that cause state transitions

## Serialization

If your state service needs to survive save/load, make it serializable:

```typescript
class GameStateService {
  score = 0;
  health = 100;
  level = 1;

  serialize() {
    return { score: this.score, health: this.health, level: this.level };
  }

  hydrate(data: { score: number; health: number; level: number }) {
    this.score = data.score;
    this.health = data.health;
    this.level = data.level;
  }
}
```

Expose this service through a game-owned `Serializable<TEncoded>` adapter, or
make the service itself implement that interface. Restore the state before
constructing the scene that consumes it.

## Anti-Patterns

- **Global mutable state** — avoid `window.score` or module-level `let score`.
  This breaks scene isolation and makes testing difficult.
- **Component-to-component direct references** — don't reach into another
  entity's components to modify their state. Use events or shared services.
- **Storing state in the UI layer** — keep game logic state in the ECS layer.
  The UI should read state, not own it.
