title: "State Management"
description: "Share game-owned state between components, scenes, UI, and save files"
---

Create state where its lifetime begins, then pass the same object to the
scenes and components that use it. A core reactive record lets gameplay update
the state while React reads it, without keeping a separate UI copy.

## Create one state root

A factory creates an independent state root for each game or run:

```typescript yage-group="game-state" yage-file="state.ts"
import { createRecord } from "@yagejs/core";

export function createGameState() {
  return createRecord({
    default: () => ({ score: 0, health: 100, level: 1 }),
  });
}

export type GameState = ReturnType<typeof createGameState>;
```

Call the factory once for a run. Passing that root to successive scenes keeps
the run's state; creating another root starts an independent run. Plugin
infrastructure uses [dependency injection](/concepts/dependency-injection/),
but game-owned score and inventory do not need service keys.

## Write from components

Use `set()` to update fields. It notifies subscribers and preserves the other
fields in the record:

```typescript yage-group="game-state" yage-file="score.ts"
import { Component, defineEvent } from "@yagejs/core";
import type { GameState } from "./state.js";

export const PointsAwarded = defineEvent<{ points: number }>(
  "my-game:points-awarded",
);

export class ScoreTracker extends Component {
  constructor(private readonly state: GameState) {
    super();
  }

  onAdd(): void {
    this.listenScene(PointsAwarded, ({ points }) => {
      this.state.set({ score: this.state.get().score + points });
    });
  }
}
```

`listenScene()` releases the subscription when the component is removed.
Use `listen()` for entity subscriptions, `listenBus()` for engine events,
and `addCleanup(unsubscribe)` for other subscription APIs.

Events let a producer award points without holding the record. A direct
reference is also valid when the producer already knows the state or component
it should update. Neither approach needs another copy of the score.

## Read the same root from React

Pass the root as a prop. `useStore()` subscribes to it and reads the selected
value on changes:

```tsx yage-group="game-state" yage-file="hud.tsx"
import { Text, useStore } from "@yagejs/ui-react";
import type { GameState } from "./state.js";

export function HUD({ state }: { state: GameState }) {
  const score = useStore(state, (source) => source.get().score);
  return <Text>{`Score: ${score}`}</Text>;
}
```

Mount the score tracker and HUD with the same root:

```tsx yage-group="game-state" yage-file="scene.tsx"
import { Scene } from "@yagejs/core";
import { UIRoot } from "@yagejs/ui-react";
import { HUD } from "./hud.js";
import { ScoreTracker } from "./score.js";
import type { GameState } from "./state.js";

export class GameScene extends Scene {
  readonly name = "game";

  constructor(private readonly state: GameState) {
    super();
  }

  onEnter(): void {
    const hud = this.spawn("hud");
    hud.add(new ScoreTracker(this.state));
    hud.add(new UIRoot()).render(<HUD state={this.state} />);
  }
}
```

The engine must have `RendererPlugin`, `UIPlugin` and `UIReactPlugin`
installed before entering this scene. See [React UI](/guides/ui-react/)
for setup.

For a running engine with those plugins installed:

```typescript yage-group="game-state" yage-file="start.ts" yage-context="engine"
import { createGameState } from "./state.js";
import { GameScene } from "./scene.js";
import { PointsAwarded } from "./score.js";

const state = createGameState();
const scene = new GameScene(state);
await engine.scenes.push(scene);
scene.emit(PointsAwarded, { points: 10 });
```

The tracker changes the record and the HUD reads the new score. Scene teardown
removes the tracker subscription and the React tree; the caller still owns the
record.

## Save durable facts

A reactive record already implements `Serializable`. Its `serialize()`
result contains data, not scenes, components or UI objects. Restore that data
before constructing the consumers:

```typescript yage-group="game-state" yage-file="restore.ts"
import { createGameState } from "./state.js";
import { GameScene } from "./scene.js";

const state = createGameState();
state.set({ score: 30 });
const saved = state.serialize();

const restored = createGameState();
restored.hydrate(saved);
const restoredScene = new GameScene(restored);
```

For storage, migrations and named slots, pass the root to
[`@yagejs/save`](/guides/save-and-load/). Larger domains can compose state
factories with `createStore()` or implement `Serializable` on a game-owned
model.

## Keep ownership explicit

- Avoid module-global mutable game state. A factory lets tests and independent
  runs construct their own roots.
- Do not register game state during repeated scene entry. Pass the existing
  root to the scene instead.
- Keep durable gameplay state outside the UI. Local UI state, such as an open
  menu tab, can stay in React.
- Do not mutate a record's `get()` result. Use its mutation methods so
  subscribers receive changes.
