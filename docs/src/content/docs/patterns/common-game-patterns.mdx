This page covers practical patterns that come up in most games built with YAGE.

## Entity Spawning

Spawn entities dynamically using `scene.spawn`:

```typescript
// Simple spawn
const bullet = this.scene.spawn("bullet");
bullet.add(new Transform({ position: firePos }));
bullet.add(new SpriteComponent({ texture: bulletTex }));
bullet.add(new RigidBodyComponent({ type: "dynamic", gravityScale: 0 }));
bullet.add(new ColliderComponent({ shape: { type: "circle", radius: 4 } }));
bullet.get(RigidBodyComponent).setVelocity(direction.scale(800));
```

For reusable entity templates, prefer an `Entity` subclass with a
`setup()` method — see the [Entity Subclasses](/patterns/entity-subclasses/)
guide:

```typescript
import { Entity, Transform, Vec2 } from "@yagejs/core";
import { GraphicsComponent } from "@yagejs/renderer";
import { RigidBodyComponent, ColliderComponent } from "@yagejs/physics";

interface CoinParams { x: number; y: number; }

class Coin extends Entity {
  override setup({ x, y }: CoinParams): void {
    this.add(new Transform({ position: new Vec2(x, y) }));
    this.add(new GraphicsComponent().draw(drawCoin));
    this.add(new RigidBodyComponent({ type: "static" }));
    this.add(new ColliderComponent({
      shape: { type: "circle", radius: 10 },
      sensor: true,
    }));
  }
}

this.scene.spawn(Coin, { x: 200, y: 300 });
```

`defineBlueprint` is still available for parametric factories where a
class would be overkill, but entity subclasses are the preferred pattern
for anything stateful — they let you add methods, fields, and `update()`
ticks alongside the construction logic.

## Entity Destruction

Destroy entities when they're no longer needed:

```typescript
entity.destroy();
```

Destruction is deferred to the end of the current frame — it's safe to call
during `update()` or event handlers.

Always check `isDestroyed` when iterating entities that might be destroyed
mid-loop:

```typescript
for (const entity of scene.getEntities()) {
  if (entity.isDestroyed) continue;
  // process entity...
}
```

Components are automatically cleaned up when their entity is destroyed.
`SoundComponent` stops playback, `RigidBodyComponent` removes the physics body.

## Parent-Child Entities

Attach child entities for health bars, indicators, or attached effects:

```typescript
const player = scene.spawn("player");
player.add(new Transform({ position: new Vec2(100, 100) }));
player.add(new SpriteComponent({ texture: playerTex }));

// Health bar follows the player
const healthBar = scene.spawn("health-bar");
healthBar.add(new Transform({ position: new Vec2(0, -30) })); // offset above
healthBar.add(new GraphicsComponent().draw(drawHealthBar));

player.addChild("healthBar", healthBar);
```

Child transforms are relative to the parent. When the parent moves, children
follow. Destroying the parent destroys all children.

## Cooldowns

Use `ProcessSlot` for cooldowns and timed abilities:

```typescript
import { Component, ProcessComponent, ProcessSlot } from "@yagejs/core";

class ShootAbility extends Component {
  private pc = this.sibling(ProcessComponent);
  private cooldown!: ProcessSlot;

  onAdd(): void {
    // slot() lives on ProcessComponent, so make sure the entity has one
    if (!this.entity.tryGet(ProcessComponent)) this.entity.add(new ProcessComponent());
    this.cooldown = this.pc.slot({ duration: 0.3 }); // 0.3s cooldown
  }

  update(): void {
    if (this.input.isJustPressed("fire") && this.cooldown.completed) {
      this.fireBullet();
      this.cooldown.start(); // begin the cooldown; completed is false until it elapses
    }
  }
}
```

The slot exposes `completed` and `running`, so you can gate actions on it.

For repeating effects, give the slot an `onComplete`, then `restart()` it:

```typescript
const wave = this.pc.slot({ duration: 0.5, onComplete: () => this.spawnWave() });
wave.start();
// later, to run it again:
wave.restart();
```

## Named states

`StateMachine` keeps a component's valid modes and transitions in one table.
Use it when a string field would otherwise be assigned from several places.

```typescript
import { Component, defineStates } from "@yagejs/core";

class GuardBrain extends Component {
  readonly mode = this.stateMachine(
    defineStates({
      patrol: { to: ["suspicious"] },
      suspicious: { to: ["patrol", "alert"], for: 0.5, next: "alert" },
      alert: { to: ["patrol"] },
    }),
    "patrol",
  );

  fixedUpdate(dt: number): void {
    if (this.mode.is("patrol") && this.seesPlayer()) {
      this.mode.go("suspicious");
    }
    if (this.mode.is("alert") && !this.seesPlayer()) {
      this.mode.go("patrol");
    }
    this.mode.tick(dt);
  }
}
```

The keys passed to `defineStates` become the state-name type. TypeScript rejects
unknown names in `to`, `next`, and `go()`. `go()` also checks the current
state's `to` list at runtime, and throws before any hook runs.

The first `tick()` runs the initial state's `enter` hook. Call `start()` from
`onAdd` when the hook should run before the first frame instead. Construction
and `hydrate()` run no hooks. Enter and exit hooks from `this.stateMachine(...)`
are attributed to the owning component when they throw.

A timed state needs a `for` and a different `next` that it can reach: its own
`to`, its parent's `to`, or a state marked `fromAny`. `for` is a number of
seconds or a function returning one. Pass the component's `dt` directly to `tick()`. The
engine has already applied scene and entity time scaling. Time past a state
boundary is discarded, so a large tick enters at most one state per level.

Calling `go()` with the current state restarts it when that state lists itself
in `to`: the `exit` hook runs, the timer resets, and the `enter` hook runs
again. A state that does not list itself ignores the call.

A few states tend to be reachable from everywhere, such as `hit` and `die`.
Mark those with `fromAny: true` instead of repeating them in every `to` list:

```typescript
defineStates({
  patrol: { to: ["windup"] },
  windup: { to: ["strike"], for: 0.2, next: "strike" },
  strike: { to: ["patrol"] },
  hit: { fromAny: true, to: ["patrol"] },
  die: { fromAny: true },
});
```

`fromAny` adds no edge from the state to itself, so a second hit does not
restart `hit` unless `hit` lists itself in `to`.

`for` also takes a function, called each time the state is entered. Use it for a
duration that comes from tuning or changes per entry. Because it runs at entry
rather than while the table is built, it can read a field the constructor
assigns after the machine field is initialized:

```typescript
class EnemyBrain extends Component {
  private readonly tuning: EnemyTuning;

  readonly mode = this.stateMachine(
    defineStates({
      patrol: { to: ["windup"] },
      windup: { to: ["strike"], for: () => this.tuning.windup, next: "strike" },
      strike: { to: ["patrol"] },
    }),
    "patrol",
  );

  constructor(tuning: EnemyTuning) {
    super();
    this.tuning = tuning;
  }
}
```

A returned value that is not finite and above 0 throws before the transition
commits, leaving the machine where it was.

When a callback can arrive after the machine has moved on, ask first:

```typescript
this.anim.playOneShot("hit", {
  onComplete: () => {
    if (this.mode.canGo("patrol")) this.mode.go("patrol");
  },
});
```

`canGo()` reports whether `go()` would move the machine, and never throws.

### Driving presentation from events

Every machine reports three events, typed with its own state names: `changed`
(`{ from, to }`), `entered` (`{ state, from }`), and `exited` (`{ state, to }`).
A presentation component can follow the machine without the table knowing
anything about animation:

```typescript
class GuardView extends Component {
  private readonly anim = this.sibling(AnimationController);
  private readonly guard = this.sibling(GuardBrain);

  onAdd(): void {
    const { mode } = this.guard;
    this.listen(mode, mode.events.entered, ({ state }) => this.anim.play(state));
  }
}
```

`this.listen` drops the subscription when the component is removed. Outside a
component, `mode.on(mode.events.entered, handler)` returns an unsubscribe
function. These events stay on the machine; they are not entity events and do
not bubble to the scene.

On a transition the order is: `exit` hook, `exited`, the state changes, `enter`
hook, `entered`, `changed`. The first entry emits `entered` with `from: null`
and no `changed`, and `hydrate()` emits nothing. A handler may not move the
machine that called it.

### Phases inside a state

A state that covers a sequence declares its phases with `states`, and the phase
entered with it as `start`:

```typescript
defineStates({
  idle: { to: ["shoot", "hit"] },
  shoot: {
    to: ["idle", "hit"], // reachable from every phase
    start: "aim",
    states: {
      aim: { to: ["fire"], for: 0.2, next: "fire" },
      fire: { to: ["recoil"], for: 0.1, next: "recoil" },
      recoil: { to: ["idle"], for: 0.3, next: "idle" },
    },
  },
  hit: { to: ["idle"] },
});
```

`go("shoot")` enters `aim`, and the phases run themselves to `recoil`, which
ends the sequence by entering `idle`. A hit landing during any phase calls
`go("hit")`: the current phase's `exit` runs, then `shoot`'s. The sequence
cannot outlive the state that holds it, so no phase is left current while the
entity is somewhere else.

`state` reads the current phase and `is("shoot")` is true throughout the
sequence. `entered` and `exited` fire at both levels, parent then phase on the
way in and phase then parent on the way out, while `changed` fires once and
names the phases. Phase names live in the same union as every other state, so they are
unique across the table. A phase may name its siblings, its parent, and
top-level states; naming another state's phase is rejected when the machine is
built. Giving the parent its own `for` and `next` puts a deadline on the whole
sequence, and that `next` has to leave the sequence. Nesting is one level deep — independent axes stay separate machines.

The machine implements `Serializable`, so a chosen save root can include it.
`serialize()` returns the current state and its elapsed time, plus the parent's
elapsed time inside a sequence, and `hydrate()` restores them without running
hooks. A component field without a leading underscore also appears in the
Inspector with its current state, elapsed time, and last transition.

Use separate machines for independent modes such as movement, control, and
attachment. Leave values derived from other state as getters. The abilities
addon remains the better fit for actions that need input intents, lanes,
priorities, holds, or timed step windows.

## Health and Damage

A simple health component:

```typescript
class HealthComponent extends Component {
  hp: number;
  readonly maxHp: number;

  constructor(maxHp: number) {
    super();
    this.hp = maxHp;
    this.maxHp = maxHp;
  }

  takeDamage(amount: number): void {
    this.hp = Math.max(0, this.hp - amount);
    if (this.hp <= 0) {
      this.entity.emit(EntityDied);
    }
  }

  heal(amount: number): void {
    this.hp = Math.min(this.maxHp, this.hp + amount);
  }

  get ratio(): number {
    return this.hp / this.maxHp;
  }
}
```

Handle damage via collision events:

```typescript
collider.onCollision((ev) => {
  if (ev.started) {
    const health = this.entity.tryGet(HealthComponent);
    const damage = ev.other.tryGet(DamageComponent);
    if (health && damage) {
      health.takeDamage(damage.amount);
    }
  }
});
```

## Scoring

Use events to decouple scoring from game objects:

```typescript
const CoinCollected = defineEvent("coin:collected");
const EnemyDefeated = defineEvent<{ points: number }>("enemy:defeated");

class GameScene extends Scene {
  private score = 0;

  onEnter(): void {
    this.on(CoinCollected, () => {
      this.score += 10;
    });

    this.on(EnemyDefeated, (data) => {
      this.score += data.points;
    });
  }
}
```

Coins and enemies emit events without knowing about the score — the scene
orchestrates state changes.

## Ground Detection with Raycasting

For platformers, use a short downward raycast to detect ground:

```typescript
class PlayerController extends Component {
  private readonly rb = this.sibling(RigidBodyComponent);
  private readonly transform = this.sibling(Transform);
  private world!: PhysicsWorld;
  private grounded = false;
  private coyoteTimer = 0;

  onAdd(): void {
    this.world = this.use(PhysicsWorldKey);
  }

  fixedUpdate(dt: number): void {
    // Raycast downward from entity center
    const hit = this.world.raycast(
      this.transform.worldPosition,
      { x: 0, y: 1 },          // down
      PLAYER_HALF_HEIGHT + 2,   // just past the feet
    );

    if (hit) {
      this.grounded = true;
      this.coyoteTimer = COYOTE_TIME;
    } else {
      this.coyoteTimer -= dt;
      this.grounded = this.coyoteTimer > 0;
    }
  }
}
```

**Coyote time** gives the player a brief window to jump after walking off a
ledge, making platforming feel more forgiving.

## Entity Finding

Find specific entities by name:

```typescript
const player = scene.findEntity("player");
```

Query entities by component:

```typescript
import { filterEntities } from "@yagejs/core";

const enemies = filterEntities(scene.getEntities(), {
  has: [EnemyTag, HealthComponent],
});
```

Or use the `QueryCache` for efficient repeated queries from systems:

```typescript
class DamageSystem extends System {
  private enemies!: QueryResult;

  onRegister(): void {
    const cache = this.use(QueryCacheKey);
    this.enemies = cache.register([HealthComponent, EnemyTag]);
  }

  update(): void {
    for (const entity of this.enemies) {
      // process each enemy with health...
    }
  }
}
```
