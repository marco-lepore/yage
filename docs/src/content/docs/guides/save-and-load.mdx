YAGE has two persistence paths:

1. **Stores + a Save instance** (this guide). Typed reactive singletons for
   settings, save slots, world facts, and progression. The default for almost
   everything.
2. **Snapshot quicksave**. Full-scene serialization via `@serializable`, used
   when you specifically want to "pause and resume the simulator." See the
   [Snapshot Quicksave guide](/guides/snapshot-quicksave/) for that path.

Most games only need stores. Reach for snapshots when stores aren't enough.

## Why stores

Most save data isn't really "the simulator's runtime state" — it's the
*intentional* facts about the game: which chests are opened, what chapter the
player is on, the current settings, the inventory. Trying to serialize a live
component graph to capture that data is fragile (closures, runtime objects,
destroyed entities). A typed store says directly what the data *is*.

Stores also avoid the trap of accidentally persisting things you don't want —
particle positions, animation phase, transient UI state — because you choose
what each store contains.

## Defining stores

YAGE gives you a **compound** store (the primary surface — one save target
with many typed leaves) and a set of **standalone** factories for one-offs.
Both live in `@yagejs/core` and are re-exported from `@yagejs/save` for
convenience.

### Compound `defineStore` (primary)

```typescript
// game/persistence/stores.ts
import { defineStore } from "@yagejs/save";

export interface Potion { name: string; quality: number }

export const game = defineStore("game", (s) => ({
  inventory:  s.map<string, number>(),
  recipes:    s.set<string>(),
  gold:       s.counter({ default: 0 }),
  reputation: s.counter({ default: 50 }),
  shelf:      s.list<Potion>(),
  day:        s.value<number>({ default: 1 }),
  settings:   s.record<{ volume: number; lang: string }>({
    defaults: () => ({ volume: 0.8, lang: "en" }),
  }),
}));

// Idiomatic per-shape ops on each leaf:
game.gold.increment(10);
game.inventory.set("moonleaf", 3);
game.recipes.add("brew-1");
const potionId = game.shelf.add({ name: "Cure", quality: 7 });

// Save the whole tree as one document:
save.autoPersist(game);
```

Leaf builder methods on `s`:

- `s.value<T>({ default, codec? })` — single typed cell.
- `s.counter({ default? })` — number with `value`, `set`, `increment`, `decrement`, `clamp(value, min, max)`.
- `s.record<T>({ defaults, codec? })` — object with shallow merge.
- `s.map<K, V>({ defaults? })` — key→value.
- `s.set<K>({ defaults? })` — keys.
- `s.list<T>({ defaults? })` — ordered list with stable monotonic ids.

The compound is one `PersistentLike`: a single storage key, atomic
`serialize`/`hydrate`, and one `autoPersist` debounce covering every leaf.
Reserved leaf keys — `id`, `version`, `subscribe`, `serialize`, `hydrate`,
`reset` — collide at definition time.

`useStore(compound)` is intentionally **not** supported. Read individual
leaves so React subscription granularity stays per-leaf.

### Standalone factories (one-offs)

When a single primitive doesn't belong inside a larger tree, the standalone
factories give you the same shape APIs with their own id, version, and
save target:

```typescript
import {
  defineRecord, defineValue, defineCounter,
  defineMap, defineSet, defineList,
} from "@yagejs/save";

export const settings = defineRecord<SettingsData>("settings", {
  version: 1,
  defaults: () => ({ audio: { music: 0.8, sfx: 1.0 }, vsync: true }),
});

export const opened    = defineSet<string>("world.opened");
export const defeated  = defineMap<string, number>("world.defeated");
export const restEpoch = defineCounter("world.restEpoch");
export const day       = defineValue<number>("world.day", { defaults: () => 1 });
export const journal   = defineList<{ at: number; text: string }>("world.journal");
```

Shape APIs (every leaf and standalone also has `.subscribe(fn): () => void`):

- `defineRecord<T>` / `s.record`: `get(): Readonly<T>`, `set(partial: Partial<T>)`.
- `defineValue<T>` / `s.value`: `get(): T`, `set(v: T)`.
- `defineCounter` / `s.counter`: `value()`, `set(n)`, `increment(by?)`, `decrement(by?)`, `clamp(value, min, max)`.
- `defineMap<K, V>` / `s.map`: `get(k)`, `set(k, v)`, `delete(k)`, `has(k)`, `entries(): Array<[K, V]>`, `size()`, `clear()`.
- `defineSet<K>` / `s.set`: `add(k)`, `delete(k)`, `has(k)`, `values(): K[]`, `size()`, `clear()`.
- `defineList<T>` / `s.list`: `add(item): number` (id), `remove(id): boolean`, `get(id)`, `update(id, partial)`, `list(): T[]`, `size()`, `clear()`.

Standalone factories additionally expose `.reset()` to restore defaults.
Codecs are bundled for the typed shapes (Set/Map/Counter/List) — you only
specify a custom `codec` on `defineRecord<T>` / `defineValue<T>` (or the
matching leaves) when `T` contains exotic types.

### Migrating from many standalones to one compound

If your game grew a `defineRecord` here, a `defineCounter` there, and
several `defineSet`s — each with its own `autoPersist` call — the compound
collapses them into one save target with atomic writes:

```typescript
// Before — three save documents, three autoPersist calls.
const progression = defineRecord<RunData>("run", { defaults: () => ({ chapter: 1, coins: 0 }) });
const deaths      = defineCounter("deaths");
const flags       = defineSet<string>("flags");
save.autoPersist(progression);
save.autoPersist(deaths);
save.autoPersist(flags);

// After — one document, one autoPersist call, atomic serialize/hydrate.
const game = defineStore("run", (s) => ({
  progression: s.record<RunData>({ defaults: () => ({ chapter: 1, coins: 0 }) }),
  deaths:      s.counter({ default: 0 }),
  flags:       s.set<string>(),
}));
save.autoPersist(game);
```

## Creating the Save instance

Construct `Save` once in your entry point. The plugin only registers it under
`SaveServiceKey` for in-game DI access — boot-time work uses `save` directly.

```typescript
// game/persistence/save.ts
import { createSave, localStorageAdapter } from "@yagejs/save";

export const save = createSave({
  adapter: localStorageAdapter({ namespace: "my-game" }),
});
```

```typescript
// game/main.ts
import { Engine } from "@yagejs/core";
import { SavePlugin } from "@yagejs/save";
import { save } from "./persistence/save.js";
import { settings, saves } from "./persistence/stores.js";

await save.restoreAll([settings, saves]);   // boot-time restore
save.autoPersist(settings);                  // stream changes back to disk

const engine = new Engine();
engine.use(new SavePlugin({ save }));
await engine.start();
```

## Settings — single document + auto-persist

Settings change rarely and should write to disk on every change. `autoPersist`
subscribes to the store and writes on every change, coalescing multiple
synchronous `set` calls into one write per microtask.

```typescript
await save.restore(settings);                       // load on boot
const stop = save.autoPersist(settings);

// Anywhere in the game…
settings.set({ audio: { ...settings.get().audio, music: 0.5 } });
// → one write fires after the current microtask
```

`stop()` removes the subscriber and cancels any pending write. For real
time-based debouncing across user interactions (e.g. throttling a slider
drag), wrap the store yourself.

## Save slots

Slots are named instances of a store. Use them for "save game" semantics.
Each slot has optional metadata persisted alongside the value (timestamp,
location, thumbnail, anything you want).

```typescript
interface RunMeta {
  location: string;
  playtime: number;
}

await save.saveSlot<RunMeta>(saves, "manual-1", {
  metadata: { location: "Forest Temple", playtime: 60 },
});

await save.loadSlot(saves, "manual-1");

const slots = await save.listSlots<RunMeta>(saves);
// [{ name: "manual-1", savedAt: 1714…, metadata: { location, playtime } }, …]

await save.deleteSlot(saves, "manual-1");
```

`loadSlot` throws `SlotNotFoundError` for missing slots.

### Continue (load latest)

```typescript
const slots = await save.listSlots(saves);
if (slots.length > 0) {
  const latest = slots.sort((a, b) => b.savedAt - a.savedAt)[0];
  await save.loadSlot(saves, latest.name);
}
```

### Multi-profile

If you have profiles (per-user save banks), use hierarchical slot names with
the `prefix` filter:

```typescript
await save.saveSlot(saves, `${profile}/manual-1`);
const profileSlots = await save.listSlots(saves, { prefix: `${profile}/` });
```

The engine doesn't formalize profile scopes — the convention lives in your
game code, which keeps the primitive simple.

## In-game access via DI

Components and scenes resolve the registered Save instance through
`SaveServiceKey`:

```typescript
import { SaveServiceKey } from "@yagejs/save";

class CheckpointOnRest extends Component {
  setup() {
    this.entity.on(Rested, async () => {
      const save = this.use(SaveServiceKey);
      await save.saveSlot(saves, "auto");
    });
  }
}
```

## Migration & versioning

Bump `version` when the data shape changes; provide `migrate` to transform
older payloads. Versioning is **per-store** for standalones and **per-tree**
for the compound — per-leaf migration is not supported in v1.

```typescript
// Standalone — migrate the record value.
defineRecord<RunData>("saves", {
  version: 3,
  defaults: () => initialRun(),
  migrate: (old, fromVersion) => {
    let v = old as Record<string, unknown>;
    if (fromVersion < 2) v = { ...v, inventory: [] };
    if (fromVersion < 3) v = { ...v, position: v.startPos ?? { x: 0, y: 0 } };
    return v as RunData;
  },
});

// Compound — one migrate on the tree. Receives the raw payload `data`
// dict and returns the new-format dict that gets dispatched to each leaf.
defineStore("run", (s) => ({
  gold: s.counter({ default: 0 }),
  day:  s.value<number>({ default: 1 }),
}), {
  version: 2,
  migrate: (old, fromVersion) => {
    const v1 = old as { gold: number };
    return { gold: v1.gold, day: { value: 7 } };
  },
});
```

`hydrate` calls `migrate` when stored version &lt; current. Newer-than-current
payloads throw `StoreVersionTooNewError`.

## Codecs

Stores serialize via a `Codec<T>`. Built-ins:

```typescript
import { jsonCodec, setCodec, mapCodec, dateCodec } from "@yagejs/save";

jsonCodec<T>()    // identity (default)
setCodec<K>()     // Set<K>     <-> K[]
mapCodec<K, V>()  // Map<K, V>  <-> [K, V][]
dateCodec()       // Date       <-> ISO string
```

`defineSet`/`defineMap`/`defineCounter`/`defineList` bundle the right codec —
you only specify a codec for `defineRecord<T>` / `defineValue<T>` (or the
matching `s.record`/`s.value` leaves) when the type contains exotic values.

## Adapters

```typescript
import { localStorageAdapter, memoryAdapter } from "@yagejs/save";

localStorageAdapter({ namespace?: string })  // browser
memoryAdapter()                              // tests + Node
```

The `SaveAdapter` interface is intentionally minimal — `read`, `write`,
`delete`, `list` over async string IO. Custom adapters (file system, IndexedDB,
cloud sync) plug in here.

## Tests

Reset every store between tests, swap in `memoryAdapter`:

```typescript
import { _resetAllStoresForTesting } from "@yagejs/core";
import { createSave, memoryAdapter } from "@yagejs/save";

beforeEach(() => {
  _resetAllStoresForTesting();
});

const save = createSave({ adapter: memoryAdapter() });
```

## Per-frame updates: don't

Stores are for *intentional* state — settings, slots, world facts. They notify
all subscribers synchronously on every change, and any UI bindings re-render.
**Don't update stores from `update(dt)` or other per-frame paths**; that's
what ECS state and `useQuery` / `useSceneSelector` are for. If you find
yourself debouncing every `set`, you're using the wrong primitive.

## When stores aren't enough

If your game genuinely needs to capture and resume the entire simulator state
(every entity, component, active process, scene stack) — for example a true
quicksave during physics simulation — see the
[Snapshot Quicksave guide](/guides/snapshot-quicksave/) for the
`@serializable` path.
