YAGE wraps [@pixi/sound](https://github.com/pixijs/sound) for audio playback.
The `@yagejs/audio` package provides channel-based mixing, a `SoundComponent` for
entity-bound audio, and a `sound()` asset factory for preloading.

## AudioPlugin Setup

```typescript
import { AudioPlugin } from "@yagejs/audio";

engine.use(new AudioPlugin({
  channels: {
    sfx:   { volume: 1.0 },
    music: { volume: 0.7 },
  },
}));
```

## Sound Assets

Use the `sound()` factory to create preloadable asset handles:

```typescript
import { sound } from "@yagejs/audio";

const CoinSfx  = sound("assets/coin.wav");
const BgMusic   = sound("assets/music.mp3");
```

Add them to your scene's `preload` array so they load before `onEnter`:

```typescript
class GameScene extends Scene {
  readonly preload = [CoinSfx, BgMusic];
}
```

## Playing Sounds

Resolve the `AudioManager` from the DI container and call `play`:

```typescript
import { AudioManagerKey } from "@yagejs/audio";

const audio = this.use(AudioManagerKey);

// Play a sound effect
audio.play(CoinSfx, { channel: "sfx" });

// Play background music (looping)
audio.play(BgMusic, { channel: "music", loop: true, volume: 0.5 });
```

Pass the handle `sound()` returned, or the alias string it registers — the
handle's `path`. The two forms can be mixed, and a sound added with
`registerSound` has no handle, so it is always played by name.

If nothing is registered under the alias, `play`, `playOnce`, `requestOnce`,
and `playRandom` throw and name it. That covers both a typo and playing a sound
the scene never preloaded.

**Play options:**

```typescript
audio.play(alias, {
  channel: "sfx",    // which channel (default: "sfx")
  volume: 1,         // instance volume 0–1 (default: 1)
  loop: false,       // loop playback (default: false)
  speed: 1,          // playback rate (default: 1)
});
```

Additional play methods:

```typescript
// Only play if not already playing via playOnce
audio.playOnce(BgMusic, { channel: "music", loop: true });

// Own one request for playback shared by alias and channel
const request = audio.requestOnce("charge", { onEnd: finishCharge });
request.release();

// Pick a random sound from an array
audio.playRandom(["step1.wav", "step2.wav", "step3.wav"], { channel: "sfx" });
```

`playOnce` holds one implicit owner for the shared playback. Repeated
`playOnce` calls return the same `SoundHandle` without adding owners, so callers
may ignore the handle. Each `requestOnce` call returns a separate
`SoundRequestHandle` with `active` and an idempotent `release()`. Releasing one
request does not stop the sound while another request or a `playOnce` owner
remains.

When the sound ends on its own, every active request becomes inactive and its
`onEnd` callback runs once. A released request receives no callback. Stopping
the shared `SoundHandle`, its channel, or all audio clears every request without
calling `onEnd`.

## Sound Handles

`play` returns a `SoundHandle` for controlling playback:

```typescript
const handle = audio.play(BgMusic, { channel: "music", loop: true });

handle.playing;        // boolean
handle.volume = 0.5;   // adjust volume
handle.speed = 1.5;    // adjust speed
handle.paused = true;  // pause/resume
handle.muted = true;   // mute/unmute
handle.stop();         // stop playback
```

You can also stop via the manager:

```typescript
audio.stop(handle);
```

## Channels

Channels group sounds for independent volume control. The default channels are
`"sfx"` and `"music"`, but you can define any channels in the config.

```typescript
// Volume control
audio.setChannelVolume("music", 0.3);
audio.getChannelVolume("music"); // 0.3

// Mute/unmute a channel
audio.muteChannel("sfx");
audio.unmuteChannel("sfx");

// Pause/resume a channel
audio.pauseChannel("music");
audio.resumeChannel("music");

// Stop all sounds in a channel
audio.stopChannel("sfx");
```

## Global Mute

```typescript
audio.muteAll();
audio.unmuteAll();
audio.stopAll();
```

## Audio Unlock

Web browsers suspend the `AudioContext` when a page loads and require a user
gesture (click, tap, or keypress) before any audio can play. `@pixi/sound`
attaches a one-shot gesture listener that resumes the context on the first
interaction, so calling `audio.play(...)` after a click just works.

What this means in practice: **any audio you schedule on page load is silent
until the user first interacts with the page**. That is expected browser
behavior, not a YAGE bug — the classic symptom is "my title music doesn't
play until I click somewhere." To handle the gap cleanly, use `onUnlock`:

```typescript
const audio = this.use(AudioManagerKey);

audio.onUnlock(() => {
  audio.play("music/title", { channel: "music", loop: true });
});
```

`onUnlock` fires synchronously if the context is already running, or once on
the next gesture that resumes it. It returns a disposer, so you can cancel a
pending registration:

```typescript
const dispose = audio.onUnlock(() => startMusic());
// …later
dispose();
// or: audio.offUnlock(startMusic);
```

Expose the pending state to the UI if you want a "tap to enable audio" hint:

```typescript
if (!audio.isUnlocked()) {
  // render a prompt; it's safe to dismiss on first click —
  // @pixi/sound will have resumed the context by then
}
```

`isUnlocked()` reflects `AudioContext.state === "running"` and is **never**
flipped by the mute/pause-on-blur flags below — it is strictly the
browser-capability check.

## Tab Visibility

Most web games go silent when the user backgrounds the tab. `AudioManager`
suspends the underlying `AudioContext` when the window loses focus and
resumes it on return:

```typescript
engine.use(new AudioPlugin({
  autoMuteOnBlur: true, // default: true
}));

// Or toggle at runtime:
audio.autoMuteOnBlur = false;
```

`autoMuteOnBlur` is delegated to `@pixi/sound`'s built-in
`WebAudioContext.autoPause`, which listens for `window.blur`/`focus` events
and pauses/resumes the entire `AudioContext`. Per-channel mutes and volumes
are untouched. Toggling the flag while the window is currently unfocused
takes effect immediately (the manager reconciles `paused` for you);
otherwise the new policy applies on the next blur event.

Pausing scenes on tab blur is a scene-lifecycle concern, not an audio one —
see [`SceneManager.autoPauseOnBlur`](/patterns/scene-management/#pause-on-tab-blur).

## Runtime Sounds

`registerSound(alias, buffer)` registers a runtime-generated `AudioBuffer`
under an alias, so it resolves and plays exactly like a preloaded sound —
through the same `AudioManager` channels, mute, and blur auto-pause. This is
the audio counterpart to the renderer's `registerTexture(key, texture)`, and
it's how a procedural-audio addon plugs a synthesized sound effect into the
engine.

```typescript
import { registerSound, AudioManagerKey } from "@yagejs/audio";

const buffer = synthesizeShot(); // any code that produces an AudioBuffer
registerSound("shoot", buffer);

const audio = this.use(AudioManagerKey);
audio.play("shoot");
```

You can call `registerSound` at module scope, before `AudioPlugin` installs:
the alias is held and added to the audio library the plugin loads.

Registered aliases are engine-global and live until you call
`unregisterSound(alias)`. Re-registering an alias replaces the entry.
Registering an alias already used by a loaded sound asset throws, since
letting a runtime buffer shadow a loaded asset would let that asset's unload
destroy the registered sound.

If a save root stores the alias, re-register the buffer under the same alias
during boot before loading that root. The `AudioBuffer` itself is runtime state
and does not belong in a controlled save payload.

```typescript
import { unregisterSound } from "@yagejs/audio";

unregisterSound("shoot");
```

`unregisterSound` is a no-op for aliases it never registered. An
`AudioBuffer` has no destroy step, so unlike `unregisterTexture` there's no
GPU resource to release.

## SoundComponent

`SoundComponent` binds a sound to an entity. The sound is automatically stopped
when the entity is destroyed.

```typescript
import { SoundComponent } from "@yagejs/audio";

entity.add(new SoundComponent({
  alias: BgMusic.path,
  channel: "music",
  loop: true,
  volume: 0.8,
  playOnAdd: true,       // start playing when the component is added
}));
```

Control playback from the component:

```typescript
const sc = entity.get(SoundComponent);
const handle = sc.play();
sc.stop();
sc.handle;  // current SoundHandle or null
```

This is useful for ambient sounds attached to world entities — the sound
lifecycle is tied to the entity lifecycle.
