YAGE plays recorded and generated sounds through Web Audio.
The `@yagejs/audio` package provides channel-based mixing, a `SoundComponent` for
entity-bound audio, and a `sound()` asset factory for preloading.

## AudioPlugin Setup

```typescript yage-context="engine"
import { AudioPlugin } from "@yagejs/audio";

engine.use(new AudioPlugin({
  masterVolume: 1, // default: 1
  channels: {
    sfx:   { volume: 1.0 },
    music: { volume: 0.7 },
  },
}));
```

## Sound Assets

Use the `sound()` factory to create preloadable asset handles:

```typescript yage-group="audio" yage-file="assets.ts"
import { sound } from "@yagejs/audio";

export const CoinSfx  = sound("assets/coin.wav");
export const BgMusic   = sound("assets/music.mp3");
```

Add them to your scene's `preload` array so they load before `onEnter`:

```typescript yage-group="audio" yage-file="assets.ts"
import { Scene } from "@yagejs/core";

class GameScene extends Scene {
  readonly name = "game";
  readonly preload = [CoinSfx, BgMusic];
}
```

Engines in one page share a decoded file. A second engine that preloads the
same path plays the first engine's decode, and the file stays loaded until
every engine that loaded it unloads it or is destroyed. Each engine must load
the file with the same `loopStart`, `loopEnd` and `rootNote`. A different value
throws an error that names the file.

## Playing Sounds

Resolve the `AudioManager` from the DI container and call `play`:

```typescript yage-group="audio" yage-context="scene-enter"
import { AudioManagerKey } from "@yagejs/audio";
import { BgMusic, CoinSfx } from "./assets.js";

const audio = this.use(AudioManagerKey);

// Play a sound effect
audio.play(CoinSfx, { channel: "sfx" });

// Play background music (looping)
audio.play(BgMusic, { channel: "music", loop: true, volume: 0.5 });
```

Pass the handle `sound()` returned, or the alias string it registers — the
handle's `path`. The two forms can be mixed, and a sound added with
`registerSound` has no handle, so it is always played by name.

If nothing is registered under the alias, `play`, `playOnce`, `requestOnce`,
and `playRandom` throw and name it. That covers both a typo and playing a sound
the scene never preloaded.

`hasSound(ref)` makes the same check and returns a boolean, so an alias built at
runtime can fall back to a default:

```typescript yage-group="audio" yage-context="scene-enter"
function playStep(surface: string) {
  const step = `sfx/step-${surface}.wav`;
  audio.play(audio.hasSound(step) ? step : "sfx/step-default.wav");
}
```

It answers registration alone. Whether audio is audible is a different
question: `isUnlocked()` covers the browser's autoplay gate, and the mute calls
below cover the rest.

**Play options:**

```typescript yage-group="audio" yage-context="scene-enter"
audio.play(CoinSfx, {
  channel: "sfx",    // which channel (default: "sfx")
  volume: 1,         // instance volume 0–1 (default: 1)
  loop: false,       // loop playback (default: false)
  speed: 1,          // playback rate (default: 1)
});
```

Additional play methods:

```typescript yage-group="audio" yage-context="scene-enter"
// Only play if not already playing via playOnce
audio.playOnce(BgMusic, { channel: "music", loop: true });

// Own one request for playback shared by alias and channel
const finishCharge = () => console.log("charge finished");
const request = audio.requestOnce("charge", { onEnd: finishCharge });
request.release();

// Pick a random sound from an array
audio.playRandom(["step1.wav", "step2.wav", "step3.wav"], { channel: "sfx" });
```

`playOnce` holds one implicit owner for the shared playback. Repeated
`playOnce` calls return the same `SoundHandle` without adding owners, so callers
may ignore the handle. Each `requestOnce` call returns a separate
`SoundRequestHandle` with `active` and an idempotent `release()`. Releasing one
request does not stop the sound while another request or a `playOnce` owner
remains.

When the sound ends on its own, every active request becomes inactive and its
`onEnd` callback runs once. A released request receives no callback. Stopping
the shared `SoundHandle`, its channel, or all audio clears every request without
calling `onEnd`.

`request.release({ fadeOut: seconds })` accepts `SoundRequestReleaseOptions`.
`fadeOut` must be finite and non-negative; omitting it or passing zero stops
immediately when the final owner releases. Other requests and `playOnce` owners keep the recording playing
at its current volume. Only the final request's fade applies.

The final request remains `active` through its fade, then becomes inactive when
the sound stops or ends. A released request receives no `onEnd` callback,
including if the recording ends during its fade. A new `requestOnce` or
`playOnce` call during the fade starts a fresh recording. Channel controls still
apply to both recordings.

## Sound Handles

`play` returns a `SoundHandle` for controlling playback:

```typescript yage-group="audio" yage-context="scene-enter"
const handle = audio.play(BgMusic, { channel: "music", loop: true });

handle.playing;        // boolean
handle.channel;        // readonly mixer channel
handle.volume = 0.5;   // per-sound volume before the channel multiplier
handle.speed = 1.5;    // adjust speed
handle.paused = true;  // pause/resume
handle.muted = true;   // mute/unmute
handle.stop();         // stop playback
```

You can also stop via the manager:

```typescript yage-group="audio" yage-context="scene-enter"
audio.stop(handle);
```

## Fades and Crossfades

Fade a handle on the audio clock. `at` is an absolute context time in seconds;
omit it to begin now. The call returns immediately.

```typescript yage-group="audio" yage-context="scene-enter"
handle.fadeTo(0, {
  at: audio.currentTime + 0.2,
  duration: 0.6,
  stopOnComplete: true,
});
```

The default curve is linear. `curve: "exponential"` requires positive start
and target values. `stopOnComplete` requires a zero target. A later volume
write replaces the automation from its start time onward. When it starts
before a `stopOnComplete` fade ends, it also cancels that stop. Writing the current
value, `handle.setVolume(handle.volume)`, holds the volume where the fade has
reached. `handle.stop()` ends playback.

Use `crossfade` to replace one playing sound with another:

```typescript yage-group="audio" yage-context="scene-enter"
import { sound } from "@yagejs/audio";

const StageMusic = sound("assets/stage.mp3");
const current = audio.play(BgMusic, { channel: "music", loop: true });

const next = audio.crossfade(current, StageMusic, {
  duration: 1.2,
  channel: "music",
  loop: true,
  volume: 0.8,
});
```

The incoming sound starts at zero and fades to the requested `volume`, or 1
when `volume` is absent. The outgoing sound fades to zero and stops. The method
returns the incoming `SoundHandle` immediately. If `channel` is absent, the
incoming sound uses the outgoing handle's channel.

`SoundHandle.volume` is the per-sound volume before master and channel multipliers.
Changing either preserves the handle volume and the current point
in an active fade.

Fades run on the audio clock. Scene pause and time scale do not affect them,
so a music fade keeps its length behind a pause menu or during slow motion. To
hold a fade, pause its handle or its channel: the playback position and the
remaining automation wait until resume. While audio waits for the first
gesture, or is held for an inactive host (`autoPause`), the audio clock stops
and every fade waits.

## Channels

Channels group sounds for independent volume control. The default channels are
`"sfx"` and `"music"`, but you can define any channels in the config.

Use `masterVolume` for an overall Sound setting while keeping independent music
and sound-effect levels:

```typescript yage-group="audio" yage-context="scene-enter"
audio.masterVolume = 0.5;
audio.setChannelVolume("music", 0.7);
audio.getChannelNames(); // ["sfx", "music"]
```

Playback volume is master volume × every parent channel volume × sound volume. For example,
master volume 0.5, channel volume 0.7 and sound volume 0.8 produce volume 0.28.
Changing master volume immediately affects playing sounds and applies to future
sounds, including channels created later. Channel and sound volumes, ongoing
fades, and mute/pause state keep their own values.

Master volume defaults to 1. Set its initial value with `AudioConfig.masterVolume`
or read and write `audio.masterVolume` at runtime. Values must be finite numbers
from 0 to 1; invalid values throw before changing state. Master volume controls
playback through this manager, including registered runtime sounds. It does not
control external audio contexts or sounds played outside the manager.

`getChannelNames()` returns a fresh, read-only array of configured and
subsequently created channel names in creation order. Silent channels remain in
the list. Playback and channel volume, mute and pause controls create unknown
channels automatically. Reading `getChannelVolume(name)` for an unknown channel
returns 1 without creating it.

```typescript yage-group="audio" yage-context="scene-enter"
// Volume control
audio.setChannelVolume("music", 0.3);
audio.getChannelVolume("music"); // 0.3

// Mute/unmute a channel
audio.muteChannel("sfx");
audio.unmuteChannel("sfx");

// Pause/resume a channel
audio.pauseChannel("music");
audio.resumeChannel("music");

// Stop all sounds in a channel
audio.stopChannel("sfx");
```

## Global Mute

```typescript yage-group="audio" yage-context="scene-enter"
audio.muteAll();
audio.unmuteAll();
audio.stopAll();
```

## Audio Unlock

Browsers may suspend audio until a trusted click, tap, or keypress. `AudioPlugin`
requests resume from those gestures. A successful resume can be asynchronous;
use `onUnlock` when work must wait for a running context. Ordinary `play`
calls made while locked remain booked on the frozen audio clock.

```typescript yage-group="unlock" yage-context="scene-enter"
import { AudioManagerKey } from "@yagejs/audio";

const audio = this.use(AudioManagerKey);

audio.onUnlock(() => {
  audio.play("music/title", { channel: "music", loop: true });
});
```

`onUnlock` fires synchronously if the context is already running. Otherwise
it fires once, when the context next starts running: after the first gesture,
or when the game comes back from the background and its audio resumes. It
returns a disposer, so you can cancel a pending registration:

```typescript yage-group="unlock" yage-context="scene-enter"
const startMusic = () => {
  audio.play("music/title", { channel: "music", loop: true });
};

const dispose = audio.onUnlock(startMusic);
// …later
dispose();
// or: audio.offUnlock(startMusic);
```

Expose the pending state to the UI if you want a "tap to enable audio" hint:

```typescript yage-group="unlock" yage-context="scene-enter"
if (!audio.isUnlocked()) {
  // Show a prompt until onUnlock confirms that the context is running.
}
```

`isUnlocked()` reflects `AudioContext.state === "running"`. It is `false`
before the first gesture, while audio is held because the game is in the
background, and until the context has resumed after the game comes back.

## Pausing in the Background

Most web games go silent when the player leaves them. `AudioManager` holds all
audio while the game is in the background — the app is inactive, the page is
hidden, or the window is unfocused — and releases it on the return:

```typescript yage-context="engine,scene-enter"
import { AudioManagerKey, AudioPlugin } from "@yagejs/audio";

engine.use(new AudioPlugin({
  autoPause: true, // default: true
}));

// Or toggle at runtime:
const audio = this.use(AudioManagerKey);
audio.autoPause = false;
```

The hold pauses the whole audio output, so a loop continues from where it
stopped rather than restarting. Channel and handle volume, mute and pause stay
as the player set them, and a sound the game had paused itself is still paused
after the return. The audio clock stops during the hold, so booked starts and
fades keep their relative timing. Toggling the setting takes effect at once,
in either direction.

What counts as "in the background" is one engine-wide answer,
`engine.host.active` — see
[Active, visible, focused](/concepts/engine-and-plugins/#active-visible-focused).
Pausing scenes is a scene-lifecycle concern, not an audio one: see
[`SceneManager.autoPause`](/patterns/scene-management/#pause-while-the-game-is-in-the-background).

## Runtime Sounds

`registerSound(alias, buffer)` registers a runtime-generated `AudioBuffer`
under an alias, so it resolves and plays exactly like a preloaded sound —
through the same `AudioManager` channels, mute, and automatic pause. This is
the audio counterpart to the renderer's `registerTexture(key, texture)`, and
it's how a procedural-audio addon plugs a synthesized sound effect into the
engine.

```typescript yage-context="scene-enter"
import { registerSound, AudioManagerKey } from "@yagejs/audio";
import { synthBuffer, synthPresets } from "@yagejs-addons/synth";

// Any code that produces an AudioBuffer; here, @yagejs-addons/synth
const buffer = synthBuffer(synthPresets.shoot());
registerSound("shoot", buffer);

const audio = this.use(AudioManagerKey);
audio.play("shoot");
```

You can call `registerSound` at module scope, before `AudioPlugin` installs:
the buffer is available to managers once they are created.

Registered aliases are engine-global and live until you call
`unregisterSound(alias)`. Re-registering an alias replaces the entry.
Registering an alias already used by a loaded sound asset throws: the asset
owns that alias until it is unloaded.

If a save root stores the alias, re-register the buffer under the same alias
during boot before loading that root. The `AudioBuffer` itself is runtime state
and does not belong in a controlled save payload.

```typescript
import { unregisterSound } from "@yagejs/audio";

unregisterSound("shoot");
```

`unregisterSound` is a no-op for aliases it never registered. An
`AudioBuffer` has no destroy step, so unlike `unregisterTexture` there's no
GPU resource to release.

## SoundComponent

`SoundComponent` binds a sound to an entity. The sound is automatically stopped
when the entity is destroyed.

```typescript yage-group="audio" yage-file="entity.ts" yage-context="entity"
import { SoundComponent } from "@yagejs/audio";
import { BgMusic } from "./assets.js";

entity.add(new SoundComponent({
  alias: BgMusic.path,
  channel: "music",
  loop: true,
  volume: 0.8,
  playOnAdd: true,       // start playing when the component is added
}));
```

Control playback from the component:

```typescript yage-group="audio" yage-file="entity.ts" yage-context="entity"
const sc = entity.get(SoundComponent);
const handle = sc.play();
sc.stop();
sc.handle;  // current SoundHandle or null
```

This is useful for ambient sounds attached to world entities — the sound
lifecycle is tied to the entity lifecycle.

## Scheduled playback and continuous loops

`at` books a start on `audio.currentTime`, independently of rendering frames.
`offset` selects a position inside the sample. `stopAt` books a stop. Stopping
a handle immediately cancels its booked start too. A start time already in the
past starts now and increments `lateStarts` in audio diagnostics.

```ts yage-context="component"
import { AudioManagerKey } from "@yagejs/audio";
const audio = this.use(AudioManagerKey);
const at = audio.currentTime + 0.15;
const motor = audio.play("motor", {
  at, offset: 0.1, loop: true, channel: "machinery", volume: 0.2,
});
motor.setSpeed(1.3, { at: at + 1, duration: 0.4 });
motor.setPan(0.7, { at: at + 1, duration: 0.4 });
motor.release({ at: at + 4, duration: 0.2 });
```

`setVolume`, `setSpeed`, `setPan`, and `setChannelVolume` accept the same
`at`, `duration`, and `curve` options. Volume is 0–1, pan is −1–1, and speed
must remain positive and finite at Web Audio's 32-bit float precision. All
numeric inputs must be finite. Loop points are seconds
inside the buffer: `loopStart` defaults to zero, `loopEnd` to its duration.

`registerSound(alias, buffer, { loopStart, loopEnd, rootNote })` stores sound
metadata with the buffer. The loop points become the sustain loop that
`loop: true` plays. `rootNote` is the MIDI pitch the recording sounds at its
original rate. The [music addon](/addons/music/) transposes notes against it.
`audio.getSoundMetadata(ref)` returns a copy of both.
`sound(path, { loopStart, loopEnd, rootNote })` sets the same metadata for a
recorded file. Handles for one file must agree on their metadata.

An automation time already in the past begins now. `crossfade` requires an
explicit start time to be at or after the current audio time.

Create a child channel with `audio.createChannel("engine", { parent: "sfx" })`.
Parent gain and mute affect already-booked voices. Parent pause and stop affect
all descendants. `removeChannel(name)` stops its voices and removes its children.
The default `sfx` and `music` channels remain when you configure extra channels.

For a custom sequencer, `addScheduler((now, horizon) => { ... })` returns an
unsubscribe function. Book sources with exact `at` values before `horizon`.
The plugin calls subscribers every `tickInterval` seconds (default 0.025),
looking `lookahead` seconds ahead (default 0.12). Background throttling or a
blocked main thread can exceed that window. The [music addon](/addons/music/)
counts and skips missed notes instead of playing them in a burst.

## Offline mix measurements

`renderAudio` runs the same voices, channels, panning, rate changes and gain
automation in an `OfflineAudioContext`. Preload or register the sources first,
then book every operation in the render plan. Configure `mix` with the same
master and channel levels used live. There is no implicit compressor or limiter.

```ts
import { renderAudio, measureAudio } from "@yagejs/audio";
const buffer = await renderAudio({ duration: 3 }, (audio) => {
  const loop = audio.play("motor", { loop: true, volume: 0.2 });
  loop.setSpeed(1.5, { at: 1, duration: 0.5 });
  loop.release({ at: 2.5, duration: 0.2 });
});
const measurements = measureAudio(
  Array.from({ length: buffer.numberOfChannels }, (_, i) => buffer.getChannelData(i)),
  buffer.sampleRate,
);
```

Measurements include duration, sample peak, RMS, clipped samples (absolute
value at least 1), and non-finite samples. They do not measure true peak,
perceptual loudness, or musical quality. Rendering covers the supplied plan;
it cannot reconstruct gameplay parameter changes that were never recorded.
Native rendering can differ by small floating-point amounts between runs or
browsers, so compare measurements with a numerical tolerance.

`audio.getDiagnostics()` reports context state, current time, active and booked
voices, scheduler count, late starts, channels and callback failures. With an
Inspector installed, the same data is available through its `audio` extension.
Unlock, scheduler and completion callbacks use YAGE's error boundary; failures
are reported and rethrown.


## Custom automation and pause-aware sequencing

`onChannelPause(name, callback)` reports effective channel pause, including its
parents. It calls the callback immediately and on changes, and returns an
unsubscribe function. A sequencer can hold its transport while that channel is
paused. Callbacks use the audio error boundary.

`AudioTimeline` holds a value over audio time as steps and linear or
exponential ramps, for a sequencer's own control values such as a layer
parameter. `set(value, at, duration?, curve?)` replaces the automation from
`at`, `valueAt(time)` reads it, and `shift(from, delta)` moves the remaining
points after a pause.
