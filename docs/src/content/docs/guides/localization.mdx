YAGE localizes text through a split of duties: **you bring the translation
library, YAGE owns the reactive binding.** Author any user-facing string as a
`msg(...)` binding, register a `LocalizationPlugin`, and every text sink — UI
text, buttons, @pixi/ui widgets, dialogue lines — re-renders on its own when
the locale changes.

YAGE deliberately writes no resolver. Key lookup, plurals, ICU or token
interpolation, and locale fallback all live behind a thin `LocalizationAdapter`
that you implement over i18next, FormatJS, Fluent, `Intl`, or a plain table.
What YAGE adds is the part a game engine is uniquely placed to own: the binding
that knows when to re-resolve.

## The binding: `msg`

`msg(id, values?, default?)` builds a `LocalizedBinding` — a plain,
serializable `{ id, values?, default? }`. It does **not** resolve to a string;
resolution happens at render time against the active adapter.

```ts
import { msg } from "@yagejs/core";

msg("hud.score", { n: 3 }, "Score: {n}");
// id = catalog key, values = interpolation args, default = fallback text
```

Bindings are immutable. To change an interpolation value, build a new binding
and set it again — setters that dedupe by equality ignore in-place mutations.
The `values` must be JSON-safe so a binding survives save/load unchanged.

Anywhere a text API accepts `LocalizableText` (which is `string |
LocalizedBinding`) you can pass either a plain string or a `msg(...)` binding.

## The adapter

The adapter is the boundary YAGE calls. A real game forwards `t()` to its i18n
library and `setLocale()` to that library's catalog load. Here is a
self-contained table adapter — the whole contract in one class:

```ts
import type { LocalizationAdapter, JsonValue } from "@yagejs/core";

const CATALOGS: Record<string, Record<string, string>> = {
  en: { "hud.score": "Score: {n}", "hud.start": "Start" },
  fr: { "hud.score": "Score : {n}", "hud.start": "Commencer" },
};

class TableAdapter implements LocalizationAdapter {
  private locale_ = "en";
  private readonly listeners = new Set<() => void>();

  get locale() {
    return this.locale_;
  }

  t(id: string, fallback: string | undefined, values?: Record<string, JsonValue>) {
    const template = CATALOGS[this.locale_]?.[id] ?? fallback ?? id;
    if (!values) return template;
    return template.replace(/\{(\w+)\}/g, (whole, key) =>
      Object.hasOwn(values, key) ? String(values[key]) : whole,
    );
  }

  subscribe(onChange: () => void) {
    this.listeners.add(onChange);
    return () => this.listeners.delete(onChange);
  }

  setLocale(next: string) {
    this.locale_ = next;
    this.listeners.forEach((l) => l());
  }
}
```

Register it with the plugin:

```ts
import { LocalizationPlugin } from "@yagejs/core";

engine.use(new LocalizationPlugin({ adapter: new TableAdapter() }));
```

Without a plugin, bindings still resolve — through a built-in identity adapter
that renders each binding's `default` (interpolating `{tokens}`) or, with no
default, its `id`. A game authored with `msg(...)` runs untranslated with no
i18n wiring at all, and gains translation the moment you register a plugin.

## Localizing each surface

Author the string as a binding; the surface re-resolves it on locale change.

### UI text and buttons

The `UISurface` / `UIPanel` builder methods and the element constructors take
`LocalizableText`. A surface binds its whole tree to the plugin when it mounts
and releases it when it unmounts — you never wire an individual element.

```ts
surface.text(msg("hud.title", undefined, "Play"));
surface.button(msg("hud.start", undefined, "Start"), { onClick });

// Interpolation is reactive both ways: it re-resolves on a locale switch, and
// you rebuild the binding to change the value.
const score = surface.text(msg("hud.score", { n: 0 }, "Score: {n}"));
score.setText(msg("hud.score", { n: 3 }, "Score: {n}"));
```

In React, pass a binding to `<Text>` or resolve one with the `useMessage` hook.

### @pixi/ui widgets

The `@yagejs/ui` wrappers around `@pixi/ui` accept bindings and re-resolve
their labels in place, keeping open and scroll state:

```ts
new PixiFancyButton({ text: msg("hud.ok", undefined, "OK") /* + views */ });

new PixiSelect({
  items: [
    msg("lang.en", undefined, "English"),
    msg("lang.fr", undefined, "French"),
  ],
  onSelect: (index) => void loc.setLocale(index === 0 ? "en" : "fr"),
  // + closedBG / openBG views
});
```

A `PixiSelect`'s option set is fixed at construction: a later `update({ items
})` is ignored (localization still refreshes the existing labels). Recreate the
component to change which options exist.

### Dialogue

Set `i18n: true` on a `DialogueController` to resolve each line through the same
plugin. In the compact script format, `#line:<id>` tags a say line or choice
with its catalog key; the authored text is the fallback.

```ts
host.add(new DialogueController({ ...createBoxDialogue(), i18n: true }));
```

```
# guard-demo
:: start
Guard: Halt! State your business.  #line:d.halt
```

In `i18n: true` mode a locale switch retranslates the on-screen line and
choices automatically (the reveal restarts). With a custom `I18nAdapter`
instead of the plugin bridge, call `controller.retranslate()` yourself after
the switch.

## Switching locale

Resolve the plugin and call `setLocale`:

```ts
const loc = engine.plugins.get("localization"); // or context.use(LocalizationKey)
await loc.setLocale("fr");
```

The switch is atomic. It awaits `adapter.setLocale(next)` — which a
library-backed adapter resolves only once the `fr` catalog is loaded and active
— then bumps a single revision counter that every bound text sink listens on.
So text never flips to a half-loaded locale. If two switches race, the last
caller wins and the superseded one commits nothing; if the adapter rejects, the
old locale is kept and the error propagates.

## Try it

The `examples/` app has a runnable `localization` example: a language picker
that retranslates a title, subtitle, an interpolated counter, and the picker's
own dropdown labels live — all behind the table adapter shown above.

## Not in this version

RTL layout, per-locale font switching, and key-extraction tooling are not yet
built. Interpolation is whatever your adapter implements — the identity adapter
does simple `{token}` substitution; a library-backed adapter gets full ICU or
plurals.
