Package YAGE games with Electron Forge and Capacitor.

- New package. `yage-pack init --target <electron|ios|android>…` writes the entry file each target boots from, the Electron shell, `forge.config.cjs` and `capacitor.config.ts`, adds the build and packaging scripts, and sets `productName`, `yage.appId` and `main` when they are absent. It keeps every file that is already there unless `--force` is passed, so the files are the game's after the first run.
- The entries `init` writes pass the host's save adapter to `boot` as `saveAdapter`: `electronSaveAdapter()` on desktop and `capacitorSaveAdapter()` on mobile. The report says that `BootOptions` needs that field, and that each `vite build --mode <target>` script needs a Vite config that maps the mode to the target's entry file and directory. The Electron shell shows a failed start in an error dialog and quits, because a packaged app's console output reaches no terminal.
- `yage-pack doctor` reports what each target's build needs and installs nothing: Node, the packages and peer versions the host adapters accept, one copy of `pixi.js` for the game and every `@yagejs` package it loads, that an Electron build's runtime packages are in the game's own `node_modules`, and then Xcode and a simulator runtime, or a JDK and the Android SDK. Packages are read from the game's `node_modules` and, for a member of an npm workspace, up to the workspace root. Each failure carries the command or setting that fixes it. For runtime packages an npm workspace installed outside the game, it links the packaging guide section that lists the npm settings that install them in the game and what each one changes.
- `yage-pack check` compares the app's identity across both hosts and checks the settings the mobile adapter depends on, so it gates every `npx cap sync` through the sync hook and every Electron package. Before `npx cap add` it names that command and skips the rules that read the native project, and before the first `npx cap sync` it names that command and skips the rules that read the copied configuration. Xcode settings are read from the App target's Release configuration, and a value inherited from the project or an xcconfig file is reported as unreadable. A missing web build's fix names the build script and the Vite mapping that script relies on. With `--release` it also refuses a development server, a keystore password in the configuration, a version that differs from `package.json`, an iOS app without a privacy manifest, an Android app that does not declare itself a game, and a package whose fuses or archive differ from the release set. The fuses are read from a macOS `.app` bundle, the `.exe` of a Windows package, or the executable passed with `--app`. The check cannot tell which file in a Linux package folder is the executable, so on Linux `package:electron` and `make:electron` stop at the release check. It writes nothing.
- `yage-pack record` writes a JSON `BuildRecord`: the app's identity, the git commit and the files that differed from it, every installed package and resolved dependency version, the toolchain, the hash of every file in the web build, and each artifact's kind, size, hash and signing state. An Electron artifact is the packaged app or any file a Forge maker wrote. On iOS the build number comes from the App target's configuration that matches `--profile`: Debug for `development`, Release for `release`.
- `electronForgeConfig()` from `@yagejs-tools/pack/forge` is what `forge.config.cjs` exports. It owns the archive, the bundle identifier and what goes into the package, adds the seven release fuses, runs the checks before and after packaging and writes the build record, which `make` extends with every file the makers wrote. It throws at config load when packages the shell loads are installed outside the game's own `node_modules`, where npm puts them for a workspace member, naming each one and linking the packaging guide section on that case. Packager settings, makers, plugins and hooks the game passes are kept, and its hooks run after YAGE's.
- `capacitorConfig()` from `@yagejs-tools/pack/capacitor` is what `capacitor.config.ts` exports. It sets the app's identity, the web directory and `ios.contentInset: "never"`, and keeps the Android Back button reaching the game. Overriding one of those throws at config load; everything else passes through.
- `hashDirectory()` and `REQUIRED_PACKAGES` are exported from the root entry, along with the `BuildRecord`, `BuildArtifact`, `CheckReport` and `CheckResult` types.
- The input is one web build per target, read from `dist-electron/` and `dist-capacitor/`. The browser build in `dist/` is untouched.
