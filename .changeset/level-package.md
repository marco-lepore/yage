New package: `@yagejs/level` loads authored level files — `*.yage-level.json` documents holding entity placements, their setup parameters, hierarchy, active state, and local transforms.

- Declare a placeable entity with `defineLevelEntity({ id, version, params, migrations })` on a static `level` field, its parameters with `defineParams`, and an asset parameter with `param.asset(descriptor, defaultPath, frames?)` over a `defineLevelAsset({ kind, create })` descriptor. `frames` is an `AssetFrames` saying how the named file is cut into a grid; its members are the renderer's `TextureSliceOptions`, so one object is both the hint an authoring tool reads and the grid half of the frame source `setup()` builds. It changes nothing about the authored path, the decoded `AssetHandle`, or the level file, and a grid that could not slice anything is reported with the other declaration problems. `param.entityRef({ types, optional? })` is the second kind: it stores another placement's id, or `null` for nothing chosen, and `setup()` receives an `EntityHandle` on the entity that placement became. `types` names the catalog type ids the slot accepts, and may name a type declared later or contributed by a package. `defineLevelProject({ entities })` lists a project's classes and `buildLevelCatalog(project)` turns them into the catalog loading needs; a bad declaration is reported there rather than thrown at import, a duplicate entity type id is an error, and so is a reference accepting no types or a type the project does not declare.
- `defaultParams(schema)` returns every declared field at its default, for a tool that creates placements. Authoring resolves defaults once, at creation, so a later change to a declaration's default leaves levels that already exist alone — which is also why a missing parameter is an error rather than a default at load time.
- `describeParams(schema)` returns immutable, data-only field descriptions for authoring tools. A description carries `kind`, which says which control the field needs and is the closed set `"asset" | "entityRef"`. An asset field also carries `assetKind`, the `kind` of the descriptor `param.asset()` was given — so a tool can tell a texture from a sound and show the right thing — and `frames` when the declaration gave one, so a tool can show one frame of a sheet instead of the whole file. A reference field carries `types` and `optional`, and its `defaultValue` is `null`. Parameter kinds are built through `param`, and catalog construction rejects hand-built lookalikes before running their callbacks. Preparation diagnostics carry stable codes for unknown types, migration failures, invalid parameters, asset-derivation failures, and the three ways a reference can be wrong — `reference-unset`, `reference-missing`, and `reference-type`; every diagnostic remains a blocking error. A prepared placement carries the placements it points at as `references`, so a tool can follow them without reading a schema.
- `readLevel(source)` parses a document — file text or already-parsed JSON — collecting every structural problem instead of throwing on the first. `prepareLevel(document, catalog)` checks it against the catalog, migrates parameters to the declared versions, and derives the assets it needs; it reports and never throws. `levelAssets(prepared)` returns those handles for a scene's `preload`, deduplicated by the key `AssetManager` counts references by. `validateLevel(document, catalog)` is preparation asked for its diagnostics alone.
- `instantiateLevel(scene, prepared, { namespace, transform?, activation? })` creates the entities, all or nothing: a prepared level carrying any diagnostic is refused, a construction failure throws `LevelLoadError` with the scene untouched, and an activation failure disposes the instance. Every entity is reserved before any `setup()` runs, so a reference parameter resolves whichever order the document lists the two placements in, and two placements may point at each other. The target's own `setup()` may not have run yet: store the handle in `setup()` and read `.current` from a component's `onEnable()` or later, which activation guarantees is after every `setup()` in the level. The returned `LevelInstance` gives placement lookup, `entities`, `activate()`, and isolated `dispose()`. `namespace` prefixes every derived scene key, so one document loads more than once in a scene.
- `loadLevelDocument(url)` fetches a level document and reads it in one call, with an error naming the URL. It is the game side of the editor's Run control, which opens the game's own page with the level's path in a `level` query parameter.
- A placement may name the render layer its visuals join, as an optional `layer` field. It moves every visual the entity type left on `"default"` and leaves one the type put somewhere else, so a type that draws a health bar on `"ui"` keeps it there. Inside one layer, draw order is the order placements are created in, which is document order; the loader builds by depth, so every child draws over every root on the same layer.
- `@yagejs/level/document` carries the parser and the canonical writer with no dependency on `@yagejs/core`, so a Node tool can read and rewrite level files without evaluating engine code. `formatLevel(document)` produces one canonical text per document.
