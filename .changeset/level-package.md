New package: `@yagejs/level` loads authored level files — `*.yage-level.json` documents holding entity placements, their setup parameters, hierarchy, active state, and local transforms.

- Declare a placeable entity with `defineLevelEntity({ id, version, params, migrations })` on a static `level` field, its parameters with `defineParams`, and an asset parameter with `param.asset(descriptor, defaultPath)` over a `defineLevelAsset({ kind, create })` descriptor. `defineLevelProject({ entities })` lists a project's classes and `buildLevelCatalog(project)` turns them into the catalog loading needs; a bad declaration is reported there rather than thrown at import, and a duplicate entity type id is an error.
- `defaultParams(schema)` returns every declared field at its default, for a tool that creates placements. Authoring resolves defaults once, at creation, so a later change to a declaration's default leaves levels that already exist alone — which is also why a missing parameter is an error rather than a default at load time.
- `describeParams(schema)` returns immutable, data-only field descriptions for authoring tools. A description carries `kind`, which says which control the field needs and is `"asset"` today, and `assetKind`, which is the `kind` of the descriptor `param.asset()` was given — so a tool can tell a texture from a sound and show the right thing. Parameter kinds are built through `param`, and catalog construction rejects hand-built lookalikes before running their callbacks. Preparation diagnostics carry stable codes for unknown types, migration failures, invalid parameters, and asset-derivation failures; every diagnostic remains a blocking error.
- `readLevel(source)` parses a document — file text or already-parsed JSON — collecting every structural problem instead of throwing on the first. `prepareLevel(document, catalog)` checks it against the catalog, migrates parameters to the declared versions, and derives the assets it needs; it reports and never throws. `levelAssets(prepared)` returns those handles for a scene's `preload`, deduplicated by the key `AssetManager` counts references by. `validateLevel(document, catalog)` is preparation asked for its diagnostics alone.
- `instantiateLevel(scene, prepared, { namespace, transform?, activation? })` creates the entities, all or nothing: a prepared level carrying any diagnostic is refused, a construction failure throws `LevelLoadError` with the scene untouched, and an activation failure disposes the instance. Every entity is reserved before any `setup()` runs, so a parameter can reference a placement further down the document. The returned `LevelInstance` gives placement lookup, `entities`, `activate()`, and isolated `dispose()`. `namespace` prefixes every derived scene key, so one document loads more than once in a scene.
- `loadLevelDocument(url)` fetches a level document and reads it in one call, with an error naming the URL. It is the game side of the editor's Run control, which opens the game's own page with the level's path in a `level` query parameter.
- `@yagejs/level/document` carries the parser and the canonical writer with no dependency on `@yagejs/core`, so a Node tool can read and rewrite level files without evaluating engine code. `formatLevel(document)` produces one canonical text per document.
