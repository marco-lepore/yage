New package: `@yagejs/level` loads authored level files — `*.yage-level.json` documents holding entity placements, their setup parameters, hierarchy, active state, and local transforms.

- Declare a placeable entity with `defineLevelEntity({ id, version, params, migrations })` on a static `level` field, its parameters with `defineParams`, and an asset parameter with `param.asset(descriptor, defaultPath, frames?)` over a `defineLevelAsset({ kind, create })` descriptor. `frames` is an `AssetFrames` saying how the named file is cut into a grid; its members are the renderer's `TextureSliceOptions`, so one object is both the hint an authoring tool reads and the grid half of the frame source `setup()` builds. It changes nothing about the authored path, the decoded `AssetHandle`, or the level file, and a grid that could not slice anything is reported with the other declaration problems. `param.entityRef({ types, optional? })` is the second kind: it stores another placement's id, or `null` for nothing chosen, and `setup()` receives an `EntityHandle` on the entity that placement became. `types` names the catalog type ids the slot accepts, and may name a type declared later or contributed by a package. The plain kinds carry the values a game is made of: `param.number(default, { min?, max?, step? })`, `param.integer(default, { min?, max? })`, `param.boolean(default)`, `param.string(default, { multiline? })`, and `param.select(default, values)`, whose values are read literally so `setup()` receives their union; given an object instead of a list it takes the choices from its keys, so the name a level stores and the code that name stands for are one declaration and `values[params.field]` is always defined. The authored JSON is the value itself. `integer` is a kind of its own rather than a rounding option on `number`, because a fraction where a whole number belongs is reported and never corrected silently. `min` and `max` are checked when a level is prepared; `step` and `multiline` are authoring data and accept every value the kind does. `param.vec2(default, options?)` and `param.point(default, options?)` carry a pair of numbers, authored as `{ "x": 12, "y": -4 }` and decoded to a `Vec2`: `vec2` is a pair — a size, a factor, a velocity — and `point` is a place, which is what lets an authoring tool draw a handle on it. `point`'s `relative: true` stores the value in the placement's own frame, so it travels with the placement when an author moves it, and `space` says which frame `setup()` receives. `space` defaults to `"world"`, so a relative point arrives as a world position with nothing left to compose: the level converts through the pose it places the entity at. `space: "local"` asks for an offset from the placement instead — a muzzle, a hardpoint — which the game turns into a world point where it uses it, through `Transform.localToWorld`. The two options are independent and all four pairings work. `param.object(fields, options?)` declares a value with members — the same record `defineParams` takes — and `setup()` receives an object of their decoded values; a member is required the way a parameter is, every member is validated and decoded by its own kind, and a new placement starts with the members' own defaults composed. `param.array(item, { default?, min?, max? })` is a list of one kind of element, with `min` and `max` as how many elements it may hold; the declared default is checked against them too, so a `min` above zero without a `default` is reported with the other declaration problems. Nesting is capped at four levels of `object` and `array`, and a deeper declaration is reported with the other declaration problems; a `param.entityRef` inside either is reported too, because what follows a reference reads one named parameter of a placement. `param.json({ default? })` accepts any JSON value and hands it over unchanged: the escape for a shape the kinds cannot describe, where nothing checks what is inside and an authoring tool can only offer the text of it. Every kind but `asset` takes `optional`, which makes `null` a value and gives `setup()` the type `T | undefined`; a key left out of a placement stays an error whichever kind it is. `defineLevelProject({ entities })` lists a project's classes and `buildLevelCatalog(project)` turns them into the catalog loading needs; a bad declaration is reported there rather than thrown at import, a duplicate entity type id is an error, and so is a reference accepting no types or a type the project does not declare.
- `defaultParams(schema)` returns every declared field at its default, for a tool that creates placements; a default that is not a primitive is copied, so two placements never share one object. Authoring resolves defaults once, at creation, so a later change to a declaration's default leaves levels that already exist alone — which is also why a missing parameter is an error rather than a default at load time.
- `describeParams(schema)` returns immutable, data-only field descriptions for authoring tools. A description carries `kind`, which says which control the field needs and is the closed set `"asset" | "entityRef" | "number" | "integer" | "boolean" | "string" | "select" | "vec2" | "point" | "object" | "array" | "json"`. A description is a tree and `kind` is flat at every node of it: an `object` field carries `fields`, its members as `ParamFieldDescription`s of their own, and an `array` field carries `item`, one `ParamValueDescription` with no name, since an element is named by its position. `ParamValueDescription` is a description without a name and `ParamFieldDescription` is that plus one, so a tool switches on `kind` the same way at every depth. An asset field also carries `assetKind`, the `kind` of the descriptor `param.asset()` was given — so a tool can tell a texture from a sound and show the right thing — and `frames` when the declaration gave one, so a tool can show one frame of a sheet instead of the whole file. A reference field carries `types`, and its `defaultValue` is `null`. A number field carries `min`, `max` and `step` when the declaration gave them, a string field carries `multiline`, a choice field carries `options`, the frozen list of values it accepts, an `array` field carries `min` and `max` as how many elements it may hold, and a `point` field carries `relative`. `optional` is on every kind, and `defaultValue` is whatever the declaration gave — a number, `true` or `false`, a string, or `null`. Parameter kinds are built through `param`, and catalog construction rejects hand-built lookalikes before running their callbacks. `ParamKind<T>` and `RuntimeValueOf<K>` are exported so an item kind, or a helper that returns one, can be named. Preparation diagnostics carry stable codes for unknown types, migration failures, invalid parameters, asset-derivation failures, and the three ways a reference can be wrong — `reference-unset`, `reference-missing`, and `reference-type`; every diagnostic remains a blocking error. A prepared placement carries the placements it points at as `references`, so a tool can follow them without reading a schema.
- `readLevel(source)` parses a document — file text or already-parsed JSON — collecting every structural problem instead of throwing on the first. `prepareLevel(document, catalog)` checks it against the catalog, migrates parameters to the declared versions, and derives the assets it needs; it reports and never throws. `levelAssets(prepared)` returns those handles for a scene's `preload`, deduplicated by the key `AssetManager` counts references by. `validateLevel(document, catalog)` is preparation asked for its diagnostics alone.
- `instantiateLevel(scene, prepared, { namespace, transform?, activation? })` creates the entities, all or nothing: a prepared level carrying any diagnostic is refused, a construction failure throws `LevelLoadError` with the scene untouched, and an activation failure disposes the instance. Every entity is reserved before any `setup()` runs, so a reference parameter resolves whichever order the document lists the two placements in, and two placements may point at each other. The target's own `setup()` may not have run yet: store the handle in `setup()` and read `.current` from a component's `onEnable()` or later, which activation guarantees is after every `setup()` in the level. The returned `LevelInstance` gives placement lookup, `entities`, `activate()`, and isolated `dispose()`. `namespace` prefixes every derived scene key, so one document loads more than once in a scene.
- `loadLevelDocument(url)` fetches a level document and reads it in one call, with an error naming the URL. It is the game side of the editor's Run control, which opens the game's own page with the level's path in a `level` query parameter.
- A placement may name the render layer its visuals join, as an optional `layer` field. It moves every visual the entity type left on `"default"` and leaves one the type put somewhere else, so a type that draws a health bar on `"ui"` keeps it there. Inside one layer, draw order is the order placements are created in, which is document order; the loader builds by depth, so every child draws over every root on the same layer.
- `@yagejs/level/document` carries the parser and the canonical writer with no dependency on `@yagejs/core`, so a Node tool can read and rewrite level files without evaluating engine code. `formatLevel(document)` produces one canonical text per document.
