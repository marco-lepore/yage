Add `@yagejs-addons/dialogue`, the first YAGE addon: a self-contained, themeable dialogue system.

- **Headless core** (root entry `.`): runner/session/types, markup parser, i18n, canonical format, `DialogueController`, events, and pixi-free input bindings over `@yagejs/input`. The root entry never transitively imports `pixi.js` or `@yagejs/renderer`.
- **Game-state via `VariableStorage`**: the bridge between a game and a conversation is installed once on the controller (`storage`, `functions`, `commands`); `play(script)` is content-only, with optional per-call overrides. Variables live in one opaque namespace backed by a Yarn-shaped `VariableStorage` (ships `MemoryVariableStorage` + `cells` two-way accessors + `compose`), persist across plays, and are seeded from a script's `declare` defaults only when absent (a game-linked value always wins). Conditions and `set` values are expression trees (`literal | varRef | call | unary | binary | group`, Yarn-modeled operators) so `gold - 50` and `has_item("key") and not rude` are plain data; `functions` supply argument-capable reads. Commands handle game mutations (`commands` map + optional `fallbackCommand`, still mirrored to `DialogueCommandEvent`); `set` / `ctx.setVar` / `handle.setVar` write through the storage (a read-only cell rejects the write — `handle.setVar` throws to the caller, while a script `set` is logged via the engine logger and ignored so it can't wedge the conversation). `defineScript()` infers variable types so `play()` returns a typed `DialogueHandle` (`setVar` / `getVars`); `DialogueController<TStorage>` is generic over its storage. Validated at load-time (references/types) and play-time (storage/functions/commands coverage), throwing `DialogueScriptError` / `DialoguePlayError`. (Replaces the earlier `params` + `onCommand` controller options.)
- **Presenters** (`./presenters` subpath): all pixi-backed rendering — Graphics chrome + canvas `SplitText`/`Text` views, avatars, composites, and factories. Zero bundled assets.
- **Zero-config `defaultTheme()`**: Graphics chrome + canvas font with native bold/italic and per-glyph effects. Bitmap fonts are an opt-in theme path (one `bitmapFont` atlas; bold/italic are synthesised, so there are no variant-atlas theme fields).
- **Exhaustive, textured theme surface**: every look-and-feel constant a default presenter reads is a `DialogueTheme` field — frame/text/choice colours and sizes, plus `caret` (blink + size), `choiceGap`, and the bubble `tailLean` — and each presenter-config field is named identically to the theme field it comes from, so re-skinning is mechanical (a test asserts every theme field reaches a presenter). `theme.textured` is a **map of named nine-slice chrome styles** (`{ frame: { texture, insets }, bubble? }`) rendered through the renderer's `createNineSlice`, so the addon keeps its zero-`pixi.js`-peer footprint. A box line chooses its frame per line via `meta.chrome`: a named style, the built-in `"none"` (no frame, for a full-bleed line), or — when it names none/an unknown one — the `"default"` style if present, else the drawn Graphics frame; the speech bubble renders the `"default"` style's `bubble`, content-sized per line. The default box choice list is content-driven — labels word-wrap and rows grow upward from the box's bottom edge to fit long or overflowing menus (capped at the screen top), with one geometry pass shared by row placement, the selection highlight, and pointer hit-testing, plus a soft-cap advisory past `softMaxChoices`.
- **Content-sized speech bubbles**: `BubbleChrome` grows to fit its wrapped text (via the renderer's `measureWrappedText`) instead of clipping at a fixed height — for bitmap fonts too, which size through the same width-first wrap-aware path as canvas text.
- **VN controls**: session-level auto-advance (`setAutoAdvance(ms | null)`) and a hold-to-confirm skip (`fullControls(choices, { skipHoldMs })`), on top of the existing hold-to-fast-forward.
- **Choice presentation — disabled options & timed choices**: a `ChoiceOption` can set `presentation: "disabled"` (default `"hidden"`) to keep a condition-failed option on screen greyed-out and non-selectable instead of filtering it (the Disco-Elysium "[Strength 8] Force the door" pattern), with an optional i18n-resolved `disabledReason`. `PresentedChoice` carries `disabled`/`disabledReason`; selection nav and pointer hover skip disabled rows (a multi-row skip fires one `DialogueSelectionChangedEvent` for the landed row), `confirm`/`choose`/pointer-commit refuse them, a step with zero *enabled* options is skipped (no soft-lock), and a spent `once` option stays hidden regardless of presentation. The default list/bubble presenters grey disabled rows and append the reason; the radial wheel greys without a reason. Timed choices ship as a documented **recipe**, not a model feature: a non-blocking `choice-timer` command before the choice plus a host-owned timer (on the game's own clock) that calls `controller.choose(default)` on expiry, cancelling/re-arming on `DialogueChoiceShownEvent` to defuse a dangling timer; `ChoiceContext` now passes the choice step's `meta` through so a custom presenter can render a countdown from `meta.timeoutMs`.
- **Lifecycle, visibility & events**: three orthogonal host levers — `setHidden(bool)` (visual-only cutscene takeover, state-preserving, persists across `stop()`/`play()`), `setPaused(bool)` (freezes the update loop + input without losing state or blocking host-driven `setVar`), and `setInputEnabled(bool)` (input focus — an unfocused conversation stays alive but consumes no device input, so the multi-instance "two conversations, one interactive" story is a one-liner). Visibility is now a first-class channel verb (`setVisible`) on every channel rather than a covert `setNameplate(undefined)` overload; a composite chrome restores its **active** variant on show (a hide/restore mid-bubble-line brings back the bubble + caret, not an empty box frame). Missing-actor/narrator lines no longer render invisibly at world origin: a speakerless line routes to the box (narrator convention) or a configurable fallback anchor, a despawned actor falls back to its last-known position, the line stays visible with its continue caret, and a dev warning routes through the engine `Logger`. Four new observation events — `DialogueRevealCompletedEvent`, `DialogueSelectionChangedEvent`, `DialogueSkipUsedEvent`, `DialogueAutoAdvanceEvent` — bubble entity → scene alongside the existing six; the reveal-completed seam is session-owned (no clobberable public field).
- **Grapheme-correct reveal**: every character count (run lengths, `[pause]` offsets, per-glyph styles, `charsPerSec`) is in graphemes via `Intl.Segmenter` — the same segmentation pixi's `SplitText` renders one glyph per — so emoji, ZWJ sequences, and combining marks stay aligned during the typewriter reveal. `splitGraphemes()` is exported from the root entry.
- **Opt-in `@experimental` radial choice presenter** under `./presenters`.

Independently versioned (not part of the `@yagejs/*` fixed group). Ships ESM + CJS with type declarations for both entry points.
