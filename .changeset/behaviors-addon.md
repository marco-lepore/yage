Add `@yagejs-addons/behaviors`, a pure-`@yagejs/core` steering (movement AI) addon: seek, flee, arrive, wander, pursue/evade, obstacle avoidance, and three flocking primitives, blended into a desired velocity.

- **Headless model** (root entry `.`, the only entry point): `Steering` blends any number of `SteeringBehavior`s by weighted sum (`weight` per behavior, default 1) then clamps the result to `agent.maxSpeed`. Ten behavior factories — `seek`, `flee` (with an optional flee-only-if-near `radius`), `arrive` (linear speed ramp inside `slowRadius`, settles inside `arriveRadius`, fires `onArrive`/`onDepart` once per crossing), `wander` (a slowly-turning circle ahead of the current heading, with an injectable `random` for deterministic tests), `pursue`/`evade` (lead a moving target by up to `maxPrediction` seconds, collapsing to plain seek/flee for a stationary one), `avoidObstacles` (look-ahead ray, steers around the closest threat in path), and `separation`/`alignment`/`cohesion` (the three boid rules, game-supplied neighbor lists). Targets, obstacles, and neighbors all accept either a static value or a `() => value` provider, resolved live each tick — a moving player needs no re-wiring.
- **`SteeringAgent`** (a `@yagejs/core` Component, the L2a host): hosts a `Steering` model, computes a desired velocity each `update(dt)`, optionally caps the turn rate via `maxAcceleration` (omit for an instant velocity snap), and applies the result. The default `apply` integrates the entity's `Transform` kinematically (`position += velocity * dt`) — zero-config for non-physics movement. Pass a one-line `apply: (v) => body.setVelocity(v)` to drive a `RigidBodyComponent` instead; the addon never imports `@yagejs/physics`. `faceHeading` rotates the Transform to match the travel direction. Live escape hatches: `agent.steering` (mutate the behavior list), `agent.velocity` (last commanded, for debug drawing), `agent.maxSpeed`, `agent.stop()`, and the inherited `enabled` flag.
- **No physics, no presenters, no `<T>` generic.** Obstacle and neighbor discovery is game-supplied arrays, not physics queries, so `@yagejs/physics` never enters the dependency closure. There is no `./presenters` subpath (steering has no view) and no entity-event stream — the one discrete consequence (arrival) surfaces via `arrive`'s `onArrive`/`onDepart` callbacks, and a game wires its own event in one line if it wants one.

Independently versioned (not part of the `@yagejs/*` fixed group), first publish `0.1.0`. Peer dependency: `@yagejs/core` only.
