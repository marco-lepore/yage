Add `@yagejs-addons/inventory`, the second YAGE addon: a slot-based inventory system with a headless model and one windowed slot view whose cell look is a swappable preset (icon grid or text rows).

- **Headless core** (root entry `.`): `defineItems` catalog (ids derived from map keys, typed end-to-end through `Inventory<TId>`), the `Inventory` model owning the annoying-but-non-trivial logic — stack merge on add with partial acceptance (`{ added, rejected, reason, slots }`), two stacking behaviors (`"multi"` per-stack caps with overflow into new slots, `"single"` one capped total stack that rejects the excess), `move` (move/merge/swap with leftover), `split`, consolidate-and-`sort` (comparators over `SortEntry`; `byCatalogOrder`/`byName`/`byCategory`/`byQuantity` shipped), cross-inventory `transfer`/`transferSlot` (only what the target accepts leaves the source; anonymous `transfer` moves fungible stacks first then data stacks, payload intact), per-stack `data` payloads that never auto-merge (anonymous `remove` drains fungible units first then data stacks, returning what left in `RemoveResult.stacks` so instance payloads are never silently destroyed), `snapshot()`/`restore()` JSON round-trips (unknown ids and bad quantities dropped and returned; a bag that shrank between saves re-flows entries past the new capacity into free slots, dropping only what no longer fits), and typed model events (`changed`/`itemAdded`/`itemRemoved`/`rejected`/`action`). The root entry never transitively imports `pixi.js` or `@yagejs/renderer`.
- **Rules in, consequences out**: what an inventory accepts is injected policy — an `accepts` predicate for section filters (a key-items pouch), an `InventoryConstraint[]` seam for capacity models beyond slot count (weight, currency caps) answering "how many more units may enter"; the most limiting constraint's `id` rides rejections as `constraintId`, and a `NaN`-returning constraint is treated as 0 (loud reject) rather than poisoning the result. What an action *does* is the game's: `ItemActionDef` declares `id`/`label` + per-stack `available` gates (`ItemDef.actions` narrows per item), invocation emits the `action` event for the game to apply, `consumes: true` removes one unit after the event (the event's `consumes` flag says so, preventing handler double-removal), `closes: true` hints the UI shut. `count`/`has`/`remove` also take a data predicate `(data, stack) => boolean`, and `find`/`findAll` return a `LocatedStack` handle that `remove(ref)`/`transfer(target, ref)` accept — so a specific instance (the key that opens the boss lair) is first-class, not just reachable by a raw slot index.
- **`InventorySession`** (headless UI orchestrator): open/close, cursor + action-menu state machine, an input-agnostic driving API (`move`/`select`/`confirm`/`cancel`/`sort`/`toggle` via the type-erased `InventorySessionDriver`), live model re-presentation (the menu re-resolves when the stack under it changes), `setInventory` for tabbed panels sharing one view, and channel contracts (`SlotsChannel` is the only required one — navigation geometry lives in the view, so the view answers "down" itself regardless of column count).
- **`InventoryController`** (a `@yagejs/core` Component): mounts presenters, mirrors model + session events onto entity→scene engine events (`InventoryItemAdded`/`ItemRemoved`/`Rejected`/`Changed`/`Action`/`Opened`/`Closed`/`SelectionChanged` — model events fire with the panel closed too), attaches the input binding (omitted `input` defaults to the FULL set, keyboard/gamepad + pointer hit-testing wired to the controller's own presenters), and exposes the host-driven seam plus `setInputEnabled` focus gating for multi-panel setups (losing focus closes an open action menu). The item-id generic is inferred from `inventory` alone — no explicit type argument at the call site.
- **Input bindings** (root, over `@yagejs/input`): `KeyboardInputBinding` (action-map polling incl. the one closed-panel control, `toggle`), `PointerInputBinding` (hover + click cells and menu rows through the presenters' `slotAtPoint`/`actionAtPoint` hit-test seams; click off an open menu dismisses it), `CompositeInputBinding`, and `inventoryControls(bundle)`.
- **Presenters** (`./presenters` subpath): one `SlotsView` — a windowed `columns × visibleRows` layout with integer-row scrolling and ▲/▼ hints — parameterized by a swappable `CellPresenter`. Two built-in presets: `iconCell` (icon via `ItemDef.icon` or a colored-tile-initial fallback + quantity badge + cursor outline) and `rowCell` (`Name ×qty` rows + highlight bar). A "list" is `columns: 1` with `rowCell`; a text menu is `columns: 2`; there is no grid-vs-list branching. Plus `DetailView`, `ActionMenuView` (anchored beside the selected cell), `InventoryChrome` (frame + title + `used/capacity` counter), all sharing one `PanelLayout` geometry owner; one pure `cellGeometry` module keeps placement, cursor, scrolling, and hit-tests in one tested source. Zero bundled assets.
- **Zero-config factory + theme**: `createInventoryPanel()` assembles a wired bundle from one flat `InventoryTheme` (`defaultInventoryTheme()` matches the dialogue addon's palette). Cell geometry is per-instance factory options (`columns`, `visibleRows`, `cellWidth`, `cellHeight`, `gap` as a number or `{ x, y }`), each defaulting from the chosen cell preset; a per-axis constraint solver fills whatever you leave unset, and an explicit `bounds` derives the missing count or extent to fit (overdetermining an axis keeps the declared values, centers, and warns). The theme is palette + text only — no layout — and gains `tileLetterColor`. `frameAlpha` translucency applies to both the panel chrome and the action-menu popup, and a few spacing/size fields are optional and derive when omitted (`descriptionSize` → `textSize - 2`, `menu.padding`/`menu.rowGap` → 10/6, `headerGap`/`detailGap` → 10/10, `tileLetterColor` → `0x1a1a2e`). Standalone vs embedded is configuration, not API: `chrome: false` + `bounds` place the panel inside a host menu, `input: null` + `closeOnCancel: false` hand driving to the host's focus handling.
- **Layers**: screen-space `INVENTORY_LAYERS` (orders 1050–1070), below the dialogue addon's so a conversation plays over an open inventory.

Independently versioned (not part of the `@yagejs/*` fixed group). Ships ESM + CJS with type declarations for both entry points.
