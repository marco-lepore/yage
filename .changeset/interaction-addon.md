Add `@yagejs-addons/interaction`, a third YAGE addon: proximity-based "walk up, see a prompt, press E" interaction, headless with no bundled presenter.

- **`Interactable`** (a `@yagejs/core` Component) marks any entity as something an `Interactor` can focus: `new Interactable({ onInteract, prompt?, radius?, priority?, enabled? })`. `prompt` and `enabled` accept either a static value or a `() => value` provider, re-resolved every frame. Self-registers into a scene-scoped registry on add and unregisters on destroy. It also exposes read-only `position`, `radius`, `priority`, `prompt`, `order`, `isEnabled()`, and its host `entity` — the per-target data a highlight outline or proximity icon reads.
- **`Interactor`** (a `@yagejs/core` Component) is the detector: `new Interactor({ range?, action?, enabled? })`. Each `update()` ranks every in-range, enabled `Interactable` in the scene into **one snapshot** from one geometry pass: `inRange` is that snapshot and `focus` is `inRange[0]`, so the two can never disagree even when a target moves between updates. In range means `distance <= range + interactable.radius`; the order is highest `priority`, then nearest, then lowest registration order. With a non-null `action` (default `"interact"`) and a resolvable `InputManager`, the interactor fires the interact edge itself; `action: null` disables auto-input for fully manual drive. `enabled` (default true) doubles as the tracking toggle: setting it false empties the snapshot immediately (emitting the transitions) and halts tracking, input polling, and `interact()`.
- **Interacting.** `interactor.interact()` acts on the focus; `interactor.interact(target)` acts on a chosen member of `inRange`, which is what a "which of these overlapping pickups do I grab?" selection UI confirms with. Either form does nothing unless the interactor is enabled, the target is in the current `inRange`, and the target is still live (host not destroyed, component not removed, `enabled` gate still true). To fire an interactable the interactor cannot reach — a scripted or remote trigger — call `interactable.interact()` directly; that skips every check and emits no interactor event.
- **Events** (on the interactor's entity, bubbling to the scene). All state is assigned before any event emits, so a handler reading `focus`/`inRange` sees the new values. `InteractionFocusChangedEvent` (`{ interactable, prompt }`) fires only when the focus or its resolved prompt text changes — the prompt-render hook. `InteractionInRangeChangedEvent` (`{ inRange }`) fires when the ranked set changes: a target enters or leaves, or two swap rank. A selection UI must listen to this one, because a *non-focused* target entering or leaving never changes the focus. `InteractionPerformedEvent` (`{ interactable }`) fires on every interaction.
- **Scene-wide queries.** `interactablesIn(scene)` lists every live registered interactable independent of any interactor's range — for an observation skill that reveals what is interactable. It drops destroyed hosts and keeps disabled ones, since whether an ungated target is still worth revealing is the game's call. The pure `selectInteractionFocus(query, candidates)` (single winner, O(n), no sort) and `rankInteractables(query, candidates)` (the full ranked set) both encode the same priority/distance/order policy, so a custom detector gets it for nothing; both are geometry only, so filter the `enabled` gate first.
- **Reach is validated at the edge, not per candidate.** `range` and `radius` must be non-negative: the in-range test compares squared distances, so a negative total would come back positive and match distant targets. `Interactor` and `Interactable` each dev-warn once on add when given a negative value, leaving the per-candidate test a plain comparison.
- **`@yagejs/input` is an optional peer.** The root entry never imports a value from `@yagejs/input` — it re-declares the well-known `"inputManager"` service id locally and only imports the `InputManager` type (erased at build), so a headless game can install this addon with zero `@yagejs/input` footprint in the built output. Present, the interactor connects automatically; absent (or unregistered), it logs one dev-mode warning and falls back to manual `interact()` calls.
- No presenters: this ships headless only. The events already carry what a bundled prompt view would need, so a `./presenters` subpath is purely additive later.

Independently versioned (not part of the `@yagejs/*` fixed group). Ships ESM + CJS with type declarations.
