Add `@yagejs-addons/interaction`, a third YAGE addon: proximity-based "walk up, see a prompt, press E" interaction, headless with no bundled presenter.

- **`Interactable`** (a `@yagejs/core` Component) marks any entity as something an `Interactor` can focus: `new Interactable({ onInteract, prompt?, radius?, priority?, enabled? })`. `prompt` and `enabled` accept either a static value or a `() => value` provider, re-resolved every frame. Self-registers into a scene-scoped registry on add and unregisters on destroy.
- **`Interactor`** (a `@yagejs/core` Component) is the detector: `new Interactor({ range?, action?, enabled? })`. Each frame it builds candidates from every enabled `Interactable` in the scene registry and picks a winner via `selectFocus` — nearest in range wins (`distance <= range + interactable.radius`), ties break by higher `priority` then lower registration order. `focus` exposes the current winner; `interact()` fires its `onInteract` and emits `InteractedEvent`, and a test or a custom controller can call it directly instead of synthesizing input. With a non-null `action` (default `"interact"`) and a resolvable `InputManager`, the interactor also fires on the action's `isJustPressed` edge itself; `action: null` disables auto-input for fully manual drive. `enabled` (default true) doubles as the tracking toggle: setting it false emits a null-focus transition immediately (if a focus was held), then halts tracking until re-enabled — flip it to pause one interactor during a cutscene, or to switch focus tracking between several.
- **`selectFocus`** (`FocusQuery`, `InteractCandidate` in) is a pure, independently unit-tested selection function — no engine dependency.
- **Selection and highlight data (no presenters).** `interactor.inRange` is every in-range, enabled interactable this frame ranked best-focus-first (`inRange[0] === focus`), and `interactor.interact(target)` fires a chosen one instead of the default focus, with the same staleness guards — enough to build a "which of these overlapping pickups do I grab?" selection UI. `interactablesIn(scene)` lists every registered interactable independent of any interactor's range (for an observation skill highlighting what's interactable), and the pure `rankCandidates(query, candidates)` orders any subset by proximity (`rankCandidates(...)[0]` equals `selectFocus(...)`). Each `Interactable` exposes read-only `position`, `radius`, `priority`, `prompt`, `order`, `isEnabled()`, and its host `entity` — the per-target data a highlight or proximity icon reads.
- **Events**: `InteractionFocusChangedEvent` (`{ interactable, prompt }`) fires only on a transition — the focused interactable changes, or its resolved prompt text changes — so a live prompt provider re-renders without spamming the listener. `InteractedEvent` (`{ interactable }`) fires on every interaction.
- **`@yagejs/input` is an optional peer.** The root entry never imports a value from `@yagejs/input` — it re-declares the well-known `"inputManager"` service id locally and only imports the `InputManager` type (erased at build), so a headless game can install this addon with zero `@yagejs/input` footprint in the built output. Present, the interactor connects automatically; absent (or unregistered), it logs one dev-mode warning and falls back to manual `interact()` calls.
- No presenters: this ships headless only. The consequence surface (`InteractionFocusChangedEvent`'s `prompt`) already carries what a bundled prompt view would need, so a `./presenters` subpath is purely additive later.

Independently versioned (not part of the `@yagejs/*` fixed group). Ships ESM + CJS with type declarations.
